# 허브

채팅을 하나로 합치지 않고, **기억을 하나로** 둡니다. 채팅은 역할마다 따로
열어도 되고, 새로 열어도 됩니다. 어느 채팅이든 시작할 때 이 폴더를 읽고,
끝낼 때 이 폴더에 남기기 때문에 이전 내용이 저절로 이어집니다.

```
hub/
  STATE.md   지금 상태 한 장 (모든 채팅이 자동으로 읽음 — CLAUDE.md)
  RULES.md   작업 지침 (자동으로 읽음)
  README.md  이 안내
  archive/   통째로 옮긴 옛 판 — 기준 문서는 지금만 적고 경위는 log·여기

  chat/      ── 채팅 운영: 누가 어디서 일하고 무엇을 넘겼나
    tabs.md       탭 번호(1 메인·2 My·3 AI·4 사람·5 점검·6 스토어), 양도·받기, 탭끼리 확인 요청
    tabs.json     탭 → 맡는 영역 (적용 범위·확인 요청이 받는 탭을 정함)
    handoff/N.md  탭마다 인계 노트 한 장 (양도할 때 덮어씀, "N번 받기")
    log/YYYY-MM.md 채팅마다 끝날 때 남기는 인계 기록 (덧붙이기만)
    ASKS.md       확인 요청: 다른 탭에 "거기서도 이렇게 되나" + 사용자에게 옛 코드 지울지 (자동 — 원본 asks.json, scripts/asks.mjs)

  work/      ── 할 일: 역할별 열린 일·넘긴 일·보고
    roles/        dev.md 기능 개발 · qa.md 내부 점검 · store.md 스토어·출시 — 맡는 일, 열린 일
    inbox.md      역할끼리 넘기는 일
    reports.md    예약 작업이 남기는 보고와 결정 대기
    forgotten.md  잊힌 일 (자동, 매일 아침 "잊힌 일 알림")
    drafts/       아직 제자리에 못 넣은 초안
    feedback/     의견함 정리 절차와 의견함 페이지 원본
    ux-issues.md  사용자가 짚은 문제 목록 (체감 점검이 판정)
    SHOTS.md      스크린샷 모음 페이지 쓰는 법

  app/       ── 앱 구조: 무엇이 있고 어떻게 맞물리나 (코드가 바뀌면 같은 커밋에서)
    FEATURES.md   기능 장부: 기능 하나 = 이름 하나 = 줄 하나, 쓰는 탭, 옛 앱 전용·지울 것·이름 정리 (자동 — 원본 scripts/features.json)
    STRUCTURE.md  앱 전체구조: 화면 흐름(손으로) + 영역별 코드·API·신호(자동) — 자동으로 읽음
    QUIZ.md       퀴즈 알고리즘
    DESIGN.md     화면 규칙(토큰·부품·검사)
    ADS.md        광고 지도 (위 손으로, 아래 자동) · ads-plan.md/json 광고 구조 맞추기 안
    data-map.md   서버가 저장하는 것 (자동)
    costs.md      비용 구조 (자동) · economics.md 손익
    MODELS.md     모델 종료 일정·대체 · model-swap.md·model-candidates.json 교체 후보
    CONTENT.md    콘텐츠 · service-map.json 서비스 지도 칸 기록 · watch.json 변경 감시 기준값
```

## 쓰는 법

- **새 채팅을 열 때:** 하고 싶은 일을 그냥 말하면 됩니다. 어느 역할인지
  분명하면 그 역할 파일을 읽고 시작합니다. 역할을 정해서 열고 싶으면
  `/hub-dev`, `/hub-qa`, `/hub-store` 중 하나로 시작하세요.
- **채팅이 길어졌을 때(양도):** 채팅은 번호 붙은 탭으로 일합니다(`chat/tabs.md`). 대화가 한 번 압축될 만큼 길어지면
  채팅이 일 단위가 끝나는 곳에서 `chat/handoff/N.md`를 남기고 "N번 양도함"이라고 알립니다. 새 채팅에서 **"N번 받기"**라고 하면 이어집니다.
  직접 끊고 싶으면 "양도해" 또는 `/pass N`.
- **채팅을 옮길 때:** 따로 정리할 필요가 없습니다. 이전 채팅이 끝날 때 남긴
  인계 기록과 역할 파일을 새 채팅이 읽습니다. 한 채팅 안에서 역할이 바뀌면
  (개발하다가 출시 노트를 쓰는 등) 그 역할 파일도 같이 읽고 같이 고칩니다.
- **기능이 여러 탭에 걸칠 때:** 고친 채팅이 그 코드가 닿는 다른 탭마다 **확인 요청**을 만들고(`chat/ASKS.md`), 받는 탭 채팅이 시작하자마자 확인해 답합니다. 옛 코드를 지울지는 사용자에게 묻습니다 — 어느 채팅이든 열면 물어봅니다.
- **역할끼리 일을 넘길 때:** `work/inbox.md`에 한 줄 적습니다. 받는 역할이 다음에
  시작할 때 가져가서 자기 열린 일로 옮깁니다.
- **자동 실행 결과를 볼 때:** 예약 작업이 찾은 것·돌려 본 결과·정할 것은 `work/reports.md`에 쌓입니다.
  사용자는 `결정:` 줄만 적으면 다음 실행이나 그 역할 채팅이 처리합니다.

## 규칙 (채팅이 지키는 것)

1. 시작: `git pull` → `STATE.md`·`RULES.md`·`app/STRUCTURE.md`·`app/FEATURES.md`(자동) → 맡은 역할 파일 → `work/inbox.md`에서 내 역할 앞으로 온 것 → `chat/ASKS.md`에서 내 탭 앞으로 온 확인 요청(먼저 답함).
   코드를 고치는 요청이면 `node scripts/scope.mjs <파일|기능>`로 닿는 탭·화면을 먼저 보고 고친다.
2. 각 역할은 **자기 파일만** 고칩니다. 다른 역할에 바라는 건 `work/inbox.md`로, 다른 탭 화면에 닿는 변경은 확인 요청으로(`scripts/asks.mjs apply`).
   `STATE.md`는 버전·결정처럼 모두에게 해당하는 것이 바뀔 때만 고칩니다.
3. 끝: 커밋하는 작업이면 같은 커밋에 역할 파일과 `chat/log/YYYY-MM.md` 한 항목을
   넣습니다. 앱 코드를 바꿨으면 `app/STRUCTURE.md`도 고치거나(흐름·탭·영역·새 파일), 로그 항목에 `- 구조: 변화 없음`. 그리고 `- 옛 것: 없음|지움 …|사용자에게 물음 <id>`. 커밋할 게 없는 채팅(질문·점검만)도 남길 게 있으면 허브만 커밋합니다.
4. 한 채팅에서 배운 것 중 다음 채팅도 지켜야 하는 것(되풀이된 실수, 사용자가 정한 방식)은 `RULES.md`에 한 줄로 더합니다.
5. 허브는 짧게 유지합니다. 끝난 일은 열린 일에서 지우고 로그에만 남깁니다.
   `STATE.md`는 한 화면, 역할 파일은 두 화면을 넘기지 않습니다.
6. 허브만 바뀐 커밋은 Vercel이 다시 배포하지 않습니다 (`vercel.json`).

## 자동으로 되는 것 (`.claude/hooks/hub.mjs`)

- **채팅 시작:** 열린 확인 요청(탭별·사용자 삭제 질문), 넘겨받은 일(`work/inbox.md`), 최근 인계 기록 두 개가 자동으로 들어갑니다.
- **대화가 길어져 압축된 직후:** 이 채팅이 지금까지 한 커밋 목록과, 그중 아직
  인계 기록이 없는 것을 다시 알려주고 역할 파일을 다시 읽게 합니다.
- **채팅이 끝나려 할 때:** 이 채팅에서 커밋한 작업이 `hub/chat/log`에 기록되지 않았으면
  끝내지 못하고 기록부터 남깁니다. `git pull`로 받은 다른 채팅의 커밋은 세지 않습니다.
- **적용 범위·옛 것:** 이 채팅이 바꾼 코드가 다른 탭 화면에 닿는데(`scripts/scope.mjs`) 확인 요청을 안 만들었으면, 로그에 `- 옛 것:` 줄이 없으면,
  새로 죽은 코드(`scripts/leftovers.mjs --check`)를 지우지도 사용자에게 묻지도 않았으면 끝내지 못합니다.
- **전체구조:** 이 채팅이 `src/`를 바꿨는데 `app/STRUCTURE.md`·`scripts/structure.json`을 안 건드렸고 로그에
  `구조:` 줄도 없으면, 또는 새 화면 파일·API·페이지가 자리표에 없으면 끝내지 못합니다. main에 push하면
  GitHub Actions(`structure`)가 자동 부분을 다시 만들어 커밋합니다.
- 커밋 없이 끝난 채팅(질문·점검만)은 강제하지 않습니다. 남길 게 있으면 채팅이 직접 남깁니다.

## 자동 작업 멈추기 (2026-11-02)

예약 작업(변경 감시·가상 사용자 점검·일일 보고·의견함 정리 등 11개)은 **자동 작업 페이지**(https://claude.ai/artifact/XoBjsNomv6XhUaP2TLtmMs)에서 하나씩 또는 "모두 멈춤/모두 재개"로 끄고 켭니다(Claude Code Remote `update_trigger` enabled, 처음 한 번 허락). 채팅에서 "변경 감시 멈춰"라고 해도 됩니다.
- 페이지 소스 `scripts/automation/index.html` — 예약 작업을 새로 만들거나 지우면 `KNOWN`(id·이름·주기·묶음)을 고쳐 같은 주소에 다시 올립니다(capabilities는 넘기지 않으면 그대로). 목록에 없는 반복 작업도 "그 밖"으로 저절로 보입니다.
- **다시 켜기 전에:** 2026-11-09 허브를 chat·work·app으로 나눴다. 켜져 있던 "변경 감시"·"AI 모델 살피기"는 프롬프트 경로를 고쳤고, **꺼 둔 작업(서비스 지도·일일 보고·잊힌 일·가상 사용자 점검 셋·의견함)은 프롬프트에 옛 경로(hub/log·hub/inbox.md·hub/roles 등)가 남아 있다** — 켤 때 그 채팅이 `update_trigger`로 경로를 새 나무대로 고친다.
- 끄는 동안 지금 도는 실행은 끝까지 가고, 건너뛴 시간은 다시 켜도 몰아서 돌지 않습니다.
- Vercel이 직접 도는 일(문제은행 미리 채우기·지운 계정 정리·사진 정리, `vercel.json`)은 여기 없음 — 문제은행은 Vercel `QBANK_FROZEN=1`, 나머지는 사람이 Vercel에서.

## 모델 교체 (예약 작업 "AI 모델 살피기", `scripts/models/`, 2026-11-01)

매주 월요일 새 모델·종료 공지·가격을 찾아(`hub/app/MODELS.md` "새 소식") 바꿀 만한 것을 **후보**로 `hub/app/model-candidates.json`에 적고,
- **손익 계산(모델 호출 없음, 후보 하나에 약 3초):** `node scripts/models/whatif.mjs cost` — 후보로 바꾼 셈 치고 비용표·손익을 다시 계산(파일은 그대로, `patch.mjs`가 그 실행에서만 바꿈). 요금제별 한 사람 한 달·가입자 1,000명당 차이.
- **품질 시험(돈이 되거나 종료가 다가온 후보만, 한 번 약 $2):** `whatif.mjs trial <id>` — 운영 서버에서 점검 사용자로 지금 모델·후보를 같은 사람·같은 문장으로(`x-sim-model-routes`), 섞고 이름을 가려 에이전트가 평가 → `trial-result <id>`. 채팅 교정 큰 문제 비율이 지금보다 2%p 넘게 높지 않으면 "같음". 받아쓰기·목소리, 길이 없는 제공자(Gemini 등)는 "시험 불가 — 사람 판단".
- **결과:** `hub/app/model-swap.md`(허브 페이지 "모델 교체" 칸) — 권함 · 시험 필요 · 시험 불가 · 지켜봄 · 안 함. **폰 알림은 "권함"이 새로 생기거나 종료 90일 안으로 들어올 때만.** 실제로 바꾸는 것은 사용자가 "바꿔줘" 한 뒤(대부분 `aiDefaults.ts` 한 줄, 서버만).

## 변경 감시 (예약 작업, `scripts/watch/`, 2026-11-01)

기능을 만드는 채팅은 기능만 만들고 push하면 됩니다. 2시간마다 예약 작업 **"변경 감시"**가 마지막으로 본 뒤 main에 들어온 코드 변경을 보고(허브·문서만 바뀌었으면 바로 끝),
- **잼(모델 없음, 약 1분):** 비용표(`plan-cost`)·손익(`sim:economics`)·광고 지도(`ads:map`)의 모든 표 칸, 퀴즈 전수 점검 원인별 수 → 기준값(`hub/app/watch.json`)과 비교.
- **제3자 리뷰:** 코드를 쓰지 않은 에이전트가 바뀐 부분만 `scripts/watch/REVIEW.md`(답 노출·오답·14개 언어·화면 규칙·돈·데이터·영역 경계·명백한 버그)로 — 큰 것은 다른 에이전트가 한 번 더 확인.
