# 화면 규칙

> 어느 채팅이든 화면(`src/components`, `src/app`)을 만들거나 고칠 때 따른다. 목적은 **채팅이 달라도 같은 앱처럼 보이게** 하는 것.
> 토큰 값은 `src/app/globals.css`의 `@theme`, 검사는 `npm run check:design`(CI `languages`에서 push마다).
> 만든 날: 2026-10-18. 앱의 성격·말투는 `PRODUCT.md`.

## 원칙

1. **새 코드는 토큰만.** 색·글자 크기·둥글기를 숫자나 hex로 직접 쓰지 않는다.
2. **옛 코드는 그 화면을 고치는 김에.** 한꺼번에 바꾸지 않는다(언어 14개 × 화면을 다시 확인해야 함). 고친 만큼 검사 숫자가 줄면 `npm run check:design -- --update`로 기준선을 낮춰 같은 커밋에.
3. **새 값이 필요하면 토큰부터.** `globals.css` `@theme`에 더하고 아래 표에 한 줄. 화면 한 곳에만 쓰는 값은 만들지 않는다.
4. **어두운 바탕 하나.** 밝은 테마는 없다. 대비를 먼저 본다(검정 위에 `-700` 같은 어두운 색 글자는 안 보임).
5. **같은 데이터, 고르는 보기 (사용자 선호 2026-10-19).** 쌓인 기록·목록을 보여주는 화면은 하나의 정답 화면을 정하지 말고,
   사용자가 보는 방식을 골라 바꿀 수 있게 한다. 아래 "보는 방식 고르기".

## 보는 방식 고르기

이미 있는 예: My "자라는 중" 망 / 그래프 / 지도(`studyMap/GrowthNetwork.tsx`, `myViewMode`), 말하는 방 대화 / 사람별 / 채팅 위주 / 통화 위주(`lib/rooms/layout.ts`).

- **데이터는 하나, 보기만 다르다.** 어느 보기로 봐도 같은 숫자·같은 항목. 보기마다 따로 불러오거나 따로 계산하지 않는다.
- **글(텍스트) 보기를 하나 둔다.** 망·그래프가 있어도 숫자와 문장으로 읽는 보기를 함께(화면 읽기·아랍어·작은 화면에도 맞음).
- **전환은 카드 오른쪽 위 작은 칩 묶음**(`aria-pressed`, 글자는 14개 언어). 보기 2~4개, 그 이상은 만들지 않는다.
- **고른 보기는 기기에 기억**: localStorage `<화면>ViewMode`, 읽기·쓰기는 try/catch, 못 읽으면 기본 보기. 학습 언어를 바꿔도 보기는 그대로.
- **기본 보기는 처음 사용자에게 가장 쉬운 것**, 데이터가 없을 때는 보기 칩을 숨기고 안내 한 줄.
- 새 보기를 더하면 사용법(?) 그림에 그 보기 한 장, 테스트는 보기 값 저장·되읽기.
- 세 번째 화면에 넣을 때 공용 부품(`ViewSwitch` + `useViewMode(key, modes, default)`)으로 뽑고 위 두 곳도 옮긴다.

## 토큰

**바탕·글자**

| 클래스 | 값 | 쓰는 곳 |
|---|---|---|
| `bg-canvas` | #000 | 앱 바탕 |
| `bg-surface` | #121212 | 카드·시트·입력창 (옛 `bg-[#121212]`) |
| `bg-surface-sunk` | #0a0a0a | 카드 안 오목한 칸 (옛 `#0a0a0a`·`#050505`·`#0e0e0e`) |
| `bg-surface-raised` | #161616 | 카드 위에 뜬 것 |
| `border-line` | 흰색 12% | 기본 테두리 (옛 `border-white/10~15`) |
| `text-ink` | #f4f4f2 | 기본 글자 |
| `bg-platinum` `hover:bg-platinum-hover` | #e8e8e4 / #f5f5f3 | 주요 버튼(글자는 검정) |
| `door-accent` `door-soft` `door-bg` | 창구마다(`[data-door=…]`, 기본은 플래티넘·검정) | 창구 소개 페이지·창구 모드 앱의 이름표(`lib/doors.ts`). 다른 화면에는 쓰지 않는다 |
| `text-slate-200 / 400 / 500` | — | 보조 글자 3단계. **회색은 slate 하나**(neutral·gray·zinc 안 씀) |

**의미색** — 의미가 있을 때만 쓴다. 꾸밈으로 색을 넣지 않는다.

| 클래스 | 뜻 |
|---|---|
| `good` (emerald) | 맞음·완료·숙지 |
| `warn` (amber) | 주의·배운 것·포인트 |
| `bad` (rose) | 틀림·오류·삭제 |
| `info` (sky) | 정보·연결(다른 탭에서 만난 표현 등) |
| violet | 말하는 방·사람·지도에서 고른 것에만(지금 쓰는 그대로) |

바탕에 깔 때는 투명도로: `bg-good/15 border-good/30 text-good`. 
**표현의 세 상태**는 정해진 색: `bg-status-mastered`(숙지) · `bg-status-learned`(배운 것) · `bg-status-pending`(알아야 할 것·만난 것). 지도 막대·점·장부 모두 이것만.

**글자 크기** (줄 높이는 물려받음)

| 클래스 | 크기 | 쓰는 곳 |
|---|---|---|
| `text-meta` | 11 | 시각·개수·작은 표시 |
| `text-caption` | 12 | 보조 설명·칩 |
| `text-note` | 13 | 카드 안 본문 |
| `text-body` | 14 | 기본 본문 |
| `text-chat` | 15 | 채팅·학습 언어 문장 |
| `text-title` | 18 | 시트·섹션 제목 |
| `text-heading` | 20 | 화면 제목 |
| `text-hero` | 34 | 창구 소개 페이지 첫 문장만(`lib/doors.ts`) |

10px·10.5·12.5px는 만들지 않는다(옛 코드는 고칠 때 11·12·13으로).
`text-xs`·`text-sm`은 줄 높이까지 정하는 Tailwind 기본이라 그대로 둬도 된다(검사 안 함). 토큰으로 바꾸면 줄 간격이 달라지니 화면을 보고 바꾼다.

**둥글기**: `rounded-full` 알약·아바타·점 · `rounded-lg` 작은 버튼·칩·입력 · `rounded-xl` 카드·말풍선 · `rounded-2xl` 시트·큰 패널. `rounded-md`·`rounded-sm`은 새로 쓰지 않는다.

**간격**: Tailwind 기본 단위(4px 배수)만. `p-[13px]` 같은 값 안 씀. 화면 좌우 여백 16px(`px-4`).

## 안내 글 (사용법·새로워진 점, 2026-10-20 사용자 결정)

- **화면에 쓰는 법 설명 글을 넣지 않는다(사용자 결정 2026-10-22, 두 번 말함):** "낱말을 누르면…", "편한 말로 써도 돼요", "줄을 누르면 번역", "아직 댓글이 없어요. 여기에 써 보세요", 그래프 읽는 법 같은 글은 화면에 두지 않고 사용법(?) 칸에만. 입력칸 안내는 이름만("댓글"·"메시지"·"{언어}로 써보세요"), 빈 화면은 무엇이 없는지 한 문장만.
  화면에 남기는 것: 상태(연결 중·받아쓰는 중·확인하는 중), 오류, 한도·비용·남은 횟수, 동의·본인인증·결정 직전 결과 안내(로그인하면 기록이 어떻게 되는지 등), 버튼·칸 이름. 접근성용 `title`·`aria-label`은 괜찮다.
  **보관 기간·삭제 권한 같은 정책 글은 화면에 두지 않는다**(개인정보 처리방침 `/privacy`에만, 사용자 2026-10-23 "불필요한 건 다 빼고 메인에 넣지 말라"). 이날 뺀 것: 대화 목록의 "메시지는/단체방 대화는 30일 보관", 팀 보관 안내, 팀 만들기 설명, 게시판 "글은 내가 지울 때까지 남아요…"·글쓰기 빈 칸 안내, 방의 "소리는 잇지 않아요…"·"언어를 정하지 않아요…".
  **사용자가 그 화면에 필요하다고 할 때만** 넣는다 — 그 결정은 여기에 날짜와 함께 적는다.
- **설명은 한 곳에만:** 사용법 칸(`src/lib/guide/content.ts`, 칸 id `GUIDE_SECTION_IDS`). 새로워진 점 항목은 `guide: "<칸 id>"`로 그 칸을 가리키고 글을 따로 쓰지 않는다(제목·글은 칸에서, "자세히" → 사용법 창의 그 칸).
- **글에 가는 길을 쓰지 않는다:** "'사람과 학습' → 'My' → '게시판'", "통화 탭에서" 같은 탭 경로 금지(`guide/chapters.test.ts`가 막음). 그 화면으로는 묶음의 "이 화면으로 가기" 버튼이 데려간다. 버튼 이름은 `{ui:키}`.
- **탭 구조가 바뀌면:** 글은 그대로, `GUIDE_CHAPTERS`에서 칸을 옮기고 `go`만 바꾼다. 화면마다 열릴 묶음은 `GuideSheet.tsx` `SCREEN_CHAPTER`.
- 새 기능 = 새 칸(heading·body·shot, 14개 언어) + id + 묶음에 넣기. 출시 땐 `RELEASE_NOTES` 항목에 그 id.
- **그림(2026-10-20 사용자 요청 "더 낫다면"):** 칸의 글이 가리키는 버튼에 노란 테두리(`capture-whats-new.mjs` `SPOTS`), **그림 안에 글은 넣지 않는다**(600px에서 안 읽히고, 14개 언어로 설명을 두 번 쓰게 됨).
  끌기처럼 정지 그림으로 안 보이는 동작만 짧은 영상(`GUIDE_CLIPS`, 5초 안팎·100KB 아래 mp4, 소리 없음·반복, 그림이 포스터). 새로워진 점은 칸의 그림을 같이 쓴다.
  모드: `guide`(My) · `guide-chat` · `guide-video` · `guide-vocab` · `guide-call` · `guide-social`(사람·게시판·단체방·방 목록), 언어마다 `--only`, 테스트 사용자 `CAPTURE_RUN`.

## 부품 (새로 만들기 전에 있는 것부터)

- 시트·팝업: `BodyLayer`로 띄움(RULES.md 4번). 전체 화면은 `FullScreenLayer`.
- 주요 버튼: `.tb-btn`(플래티넘) · 패널: `.tb-panel` · 하단 탭: `.tb-nav` (globals.css).
- 표현 상태 점·막대: `studyMap/TopicItems.tsx` `ItemBar`.
- 같은 모양을 세 번째 만들게 되면 부품으로 뽑는다(`src/components/`에 이름 붙여). 뽑았으면 여기 한 줄.

## 언어·방향

- 학습 언어 문장은 `dir="auto"`, 여백은 `ms-`/`me-`(아랍어). `ml-`/`mr-`/`left-`/`right-`는 방향이 상관없을 때만.
- 문구 길이는 독일어·힌디어에서 1.5배까지 늘어난다. 버튼·칩에 너비를 고정하지 않는다.
