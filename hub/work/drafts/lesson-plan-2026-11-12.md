# 수업 계획 — 🎓 수업 통화가 "교재 있는 수업"이 되게 (설계안, 2026-11-12)

> 사용자 2026-11-12 "수업계획 설계해줘". 바탕은 `call-modes-2026-11-06.md` 4절(수업 모드)·5절(숙제 한 바퀴) — 거기서 정한 것(분량 없음, 학습자가 넘김, 상황극 없음, 문 넷)은 그대로 두고 **무엇을 어떤 순서로 가르치고, 어떻게 다음 수업으로 잇는지**를 코드 단위로 정한다.
> 같은 날 수업 통화 화면의 육각형을 뺐다(log 2026-11-12). 지금 수업 통화는 "부족한 칸 이름 하나"(`roleplay/studyPicture.ts`)만 겨냥한다 — 이 설계가 그 자리를 대신한다.

## 1. 지금과 바뀌는 것 한눈에

| | 지금 | 이 설계 |
|---|---|---|
| 무엇을 | 부족한 칸 이름 하나(예: "동사 활용") | **소재 줄** — 문장구조(틀) 1~3개, 틀마다 넣을 낱말 2~3개 |
| 순서 | 없음, 튜터가 대화로 | 소재마다 **보여 주기 → 끌어내기 → 옮겨 쓰기**, 고치기는 어느 단계에서나 |
| 넘기기 | 없음 | 학습자가 말로("다음")나 ⏭, 두 번 맞게 쓰면 튜터가 한 번 물음 |
| 숙제 | 이번 통화 고친 말 + 장면 조각 | + 오늘 소재의 사다리 문제 + 다음 소재 예습 한두 개 |
| 다음 수업 | 이어짐 없음 | **숙제 리뷰로 시작**, 멈춘 소재에서 이어 감 |
| 진도 | 없음 | 소재마다 "말로 맞게 씀" 기록 → 단계 안 틀을 다 쓰면 다음 단계 |

모델 호출 수는 그대로(차례마다 감독 한 번 + 끝에 장면 한 번). 계획은 규칙으로 이 폰에서 만든다(모델 없음).

## 2. 재료 — 이미 있는 것만

| 재료 | 어디 | 쓰는 곳 |
|---|---|---|
| 문장구조(틀) 14개 언어 × 1~5단계 약 90~100개 — 틀 모양·핵심 조각(`core`)·뜻·예문(빈칸 낱말·앱 언어 단서)·문법·표현 연결 | `curriculum/frames/<언어>.ts` | 소재의 몸통 |
| 체크 셋(처음 봄·다시 볼 것·앎) — 퀴즈 답으로만 움직임 | `curriculum/checkState.ts` | 고르는 순서 |
| 대화에서 쓴 수(`talkCounts`)·고친 말(`tutorFixes.v1`) | `curriculum/wordUse.ts`·`roleplay/fixMemory.ts` | "알지만 말로 안 나옴" 찾기 |
| 사다리 칸(1 알아보기 ~ 4 문장 만들기) | `curriculum/ladder.ts` | 숙제 문제 모양 |
| 첫 측정 시작 단계(표현·문법) | `curriculum/firstCheck.ts` | 처음 수업 단계 |
| 숙제 [퀴즈 \| 대화]·장면 | `roleplay/homeworkQuiz.ts`·`replay.ts` | 숙제 틀 그대로 |
| 꼴 실수 확인(`formSlip`) | `roleplay/practice.ts` | 틀을 맞게 썼나 모델 판정을 규칙으로 한 번 더 |

새 데이터(문장·낱말)는 만들지 않는다.

## 3. 수업 계획 (`roleplay/lessonPlan.ts`, 순수 · 모델 없음)

```ts
type LessonItem = {
  key: string;            // "f|en-f2-07" — 장부·사다리와 같은 열쇠
  start: "show" | "draw"; // 어느 단계부터
  why: "carry" | "review" | "apply" | "hard" | "new";
  words: string[];        // 틀에 넣을 낱말 2~3개(예문 slot 중 학습자가 퀴즈로 앎 표시한 것 먼저)
};
type LessonPlan = { language: string; stage: number; items: LessonItem[]; at: number };
type LessonSpot = { key: string; step: "show" | "draw" | "move" | "done"; right: number }; // 멈춘 자리
```

**고르는 순서** — 위에서부터 채워 최대 3개(한 통화에 다 못 해도 됨, 분량은 학습자가 정함):

1. **carry** — 지난 수업에서 멈춘 소재(`LessonSpot`, done 아님). 그 단계부터.
2. **review** — 지난 숙제에서 틀리거나 안 푼 틀. `draw`부터(숙제 리뷰가 첫머리, 5절).
3. **apply** — 체크 셋 **앎**인데 대화에서 맞게 쓴 적 없는 틀(지금 단계 이하). `draw`부터 — 보여 줄 필요 없이 바로 쓰게. *"맞힌 것은 저절로 다시 내지 않는다"는 퀴즈 규칙이고, 이건 말하기 쪽이라 겹치지 않는다.*
4. **hard** — 다시 볼 것인 틀. `show` 짧게 → `draw`.
5. **new** — 지금 단계에서 아직 안 다룬 틀, 틀 파일 순서. `show`부터.

같은 순서 안에서는 지난 통화들에서 덜 나온 기능 갈래(`fn` — 자유대화 겨냥 `talkAims.ts`가 쓰는 차례 셈) 먼저. 같은 기록이면 같은 계획(테스트 가능).

**단계:** 처음 수업은 첫 측정의 문법·표현 단계 중 낮은 쪽(없으면 1). 그 단계 틀을 모두 "말로 맞게 씀"(6절)이 되면 다음 단계.

## 4. 통화 한 번의 흐름

```
열기 ── 숙제 있음? ──예──▶ ① 숙제 리뷰 ──┐
  └─아니오(첫 수업이면 안부)────────────┴─▶ 소재 1: ② 보여 주기 → ③ 끌어내기 → ④ 옮겨 쓰기 ─▶ 소재 2 …
                                              (⑤ 고치기는 어느 단계에서나 — 지금 수업 교정 그대로)
끝내기 ─▶ 멈춘 자리 저장 · 숙제 고르기(5절) · 끝 화면
```

| 단계 | 튜터가 하는 일 | 넘어가는 조건(앱이 판단) |
|---|---|---|
| ② 보여 주기 `show` | 그 틀이 자연스러운 상황을 깔고 **자기 이야기로 그 틀을 두 번** 씀, 학습자에게 쉬운 질문 하나 | 학습자가 한 번 답하면(틀을 안 써도) |
| ③ 끌어내기 `draw` | 그 틀이어야 답할 수 있는 질문(넣을 낱말 하나를 화제로) | 틀을 맞게 한 번 씀 |
| ④ 옮겨 쓰기 `move` | 다른 장면·다른 낱말로 같은 틀이 필요한 질문 | 맞게 한 번 더 → `done`, 튜터가 "다음 거 할까요?" 한 번 |
| ⑤ 고치기 | 지금 🎓 그대로 — 큰 실수 짚기 → 고친 문장 → 다시 말해 보기(꼴 실수는 miss) | 단계는 그대로 |

- **넘기기:** 학습자가 "다음"·"next"류를 말하면 감독이 `step: "skip"`, 또는 ⏭(아이콘만). 넘긴 소재는 `done`이 아니라 멈춘 자리로 남아 다음 계획의 carry가 되지 않고 **review 쪽**으로(숙제에 들어감).
- **소재가 다 끝나면** 자유대화처럼 이어 감(교정은 수업 방식 그대로). 새 소재를 억지로 꺼내지 않는다.
- 학습자가 다른 화제로 가면 따라가고, 다음 질문에서 소재로 돌아온다(지금 `topic_change` 처리).

## 5. 숙제와 숙제 리뷰

**숙제 [퀴즈 | 대화]는 그대로**, 퀴즈 칸 고르기만 넓힌다(최대 8):

| 몫 | 무엇 | 문제 모양 |
|---|---|---|
| ~3 | 이번 통화 고친 말 | 지금처럼 틀린 곳 고치기 |
| ~3 | 오늘 다룬 소재(done·skip) | 사다리 지금 칸(`rungOf`) — 이미 `QuizPlayer`가 내는 모양 |
| ~2 | 다음 소재 예습 | 사다리 1칸(알아보기)부터 |

대화 칸은 지금 장면 그대로. 숙제 답은 퀴즈 답이라 체크 셋·사다리를 움직인다(지금 규칙 그대로).

**다음 수업 첫머리 리뷰**(감독 지시에 한 덩어리로):
- 틀린 문제 → 그 문장을 말로 다시 시킴(앱 언어 단서만 주고, 답 문장은 안 보임).
- 다 맞힘 → 그 틀로 응용 질문 하나.
- 안 풂 → 통화 안에서 말로 같이(벌·잠금 없음).
- 리뷰는 한두 차례로 끝내고 소재 1로.

학습자가 쓴 틀린 답은 이 폰에만, 다음 통화 요청 때만 보냄(`tutorFixes.v1`과 같은 방식) — 서버에 남기지 않는다.

## 6. 감독(director)에 싣는 것

요청에 지금 `study` 한 줄 대신:

```ts
lesson?: { pattern: string; meaning: string; words: string[]; step: "show"|"draw"|"move"; review?: string };
```

- `pattern`·`words`는 학습 언어, `meaning`은 앱 언어 한 줄. **예문은 넣지 않는다**(RULES "모델에게 베낄 예문 금지").
- 답에 칸 하나 추가: `"frame": "right" | "wrong" | ""` — 이번 학습자 말이 그 틀을 썼나.
- **앱이 한 번 더 본다:** 틀의 `core` 조각이 학습자 말에 있나(`wordSegments` — ja/zh/th 띄어쓰기 없음, ko 조사 붙음 허용) + `formSlip`. 모델이 right라도 core가 없거나 꼴이 틀리면 wrong. (11-12 꼴 실수 고침과 같은 방식)
- 단계 넘기기는 앱이 정하고 다음 요청의 `step`으로 알린다 — 모델이 진도를 정하지 않는다.

## 7. 기록 — 앎과 말하기는 따로(STATE 결정 그대로)

- 수업 통화의 `frame: right/wrong`은 **말하기 쪽 기록**(장부 `src: call`, 쓴 곳·활용)에만. 체크 셋은 숙제 퀴즈 답으로만 움직인다.
- "말로 맞게 씀"(3절 apply·단계 오르기) = 그 틀을 통화·채팅에서 right로 쓴 적 있음.
- 멈춘 자리·계획: `lessonPlan.v1.<언어>`(이 폰). 서버 새 저장 없음 → `data-map.json` 변화 없음.
- 오늘의 학습 📞 수업 ✓는 지금 규칙 그대로(오늘 수업 통화 한 번).

## 8. 화면 (앱 빌드 필요한 부분)

- **칠판 카드:** 보여 주기 단계에서만 튜터 얼굴 아래(육각형이 있던 자리)에 틀 모양 한 줄(`My name is ___.`). 끌어내기·옮겨 쓰기에서는 **숨긴다** — 답이 화면에 보이면 안 됨(RULES 11 ①).
- **⏭** — `CallControls`에 아이콘만(aria-label 14개 언어 문구 하나).
- 설명 글 없음. 단계 이름·진도 숫자도 통화 화면엔 없음.
- 끝 화면 통화 정리에 "오늘 다룬 틀" 줄은 따로 만들지 않는다 — 같이 배우기 칩이 이미 그 틀을 연다.

## 11. 정할 것 (사용자)

1. **소재 단위:** 틀(문장구조)만으로 할까, 표현·문법 칸(`e|`·`g|`)도 따로 소재로 넣을까? — 안: 틀만(틀이 이미 문법·표현 번호를 갖고 있어 숙제 사다리에서 같이 나옴).
2. **단계 오르기 기준:** "그 단계 틀을 모두 말로 맞게 씀"이 너무 길면 "80%"로?
3. **칠판 카드:** 보여 주기에서 틀 한 줄을 화면에 띄울까, 소리·자막만으로 할까?
4. **(전부터 대기)** 수업 통화를 장부에서 `call` 대신 학습으로 셀지 — 이 설계는 "말하기 쪽"으로 둔다.
