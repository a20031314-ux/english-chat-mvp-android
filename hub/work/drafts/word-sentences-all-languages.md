## 2. 에이전트 나누기

**원칙: 언어 하나 = 쓰는 에이전트 하나 = 파일 하나.** 한 언어의 예문은 `src/lib/curriculum/word-sentences/<언어>.json` 한 파일에 merge되므로, 같은 언어를 둘이 쓰면 merge·rebase가 부딪힌다. 언어끼리는 파일이 달라 13개를 동시에 돌려도 충돌이 없다.

| 역할 | 몇 | 하는 일 | 누가 |
|---|---|---|---|
| 짜는 쪽(계획) | 스크립트 하나 | 언어마다 묶음 계획 `scripts/story/plan/<언어>.json` — 낱말 40개·무대 둘·인물 이름·상태 | `scripts/story/plan.ts`(모델 없음) |
| 쓰는 쪽 | 언어마다 1 (13) | 다음 묶음 받기 → 이야기 둘 쓰기 → 나눔 검사 → merge → 5묶음마다 테스트·커밋·push | Cursor 구독 에이전트(RULES "고정 문장 생성은 Cursor 먼저") |
| 보는 쪽 | 언어 묶음마다 1 (쓰는 쪽과 다른 세션) | 커밋된 묶음에서 20줄 표본 — 어색함·뜻 어긋남·답 샘·번역 틀림 → 고칠 줄 목록 | Cursor 다른 세션 또는 이 채팅(탭 2) |
| 모으는 쪽 | 이 채팅(탭 2) | 진행표·수치, 고칠 줄 반영(`--replace`), 허브 기록, 막힌 언어 규칙 고치기 | Claude |

**동시에 몇 개:** 13개를 한꺼번에 돌릴 수 있으면 언어마다 하나씩. 한도가 있으면 세 물결로(채움 낮은 순, 띄어쓰기 없는 언어를 한 물결에 몰지 않음):
1. zh · pt · id · ru · it
2. ja · th · vi · hi
3. fr · ar · ko · es

**큰 언어를 둘로 나누고 싶을 때:** 쓰는 쪽 둘이 단계(4·5 / 6)로 나눠 **tsv만** 쓰고, merge·커밋은 한 쪽(또는 모으는 쪽)만. 계획 파일에서 묶음을 "맡음"으로 표시해 같은 묶음을 둘이 잡지 않는다.

## 3. 이야기 짜기와 나누기

### 묶음 만들기 (plan.ts)
- `--todo` 순서(단계 낮은 것부터) 그대로, **같은 단계 안에서만** 묶는다 — 한 이야기 안 문장 난이도가 고르게.
- 낱말 사전의 주제 칸(work·health·nature·home·food·travel·shopping·society·people·feelings·time …)으로 나눈다.
  - **주제 낱말(명사 대부분)** 약 24개: 같은 주제 또는 가까운 주제 둘.
  - **어디나 들어가는 낱말**(actions·describing·function — 동사·형용사·부사) 약 16개: 그 단계의 것을 고루 섞어 채운다.
- 한 묶음 = 36~40낱말. 끝에 남는 몇 개는 다음 묶음에 붙인다.

### 무대 둘 (같은 낱말, 다른 상황)
- 무대 목록 약 30개를 주제에 붙여 둔다(언어 공통, `scripts/story/settings.json`):
  - work: 사무실·공장·식당 주방·건설 현장
  - health: 병원·약국·체육관·수의사
  - nature: 산·바다·농장·캠핑
  - home: 이사·집 고치기·명절 가족
  - food: 시장·요리 교실·식당
  - travel: 기차·공항·호텔
  - shopping: 가게·온라인 주문
  - society: 학교·도서관·경찰서·법원·박물관·연극
  - people·feelings: 친구·이웃·결혼식
  - time: 하루 일과·계절
- 묶음마다 **무대 A = 묶음 주제와 맞는 곳, 무대 B = 다른 주제의 곳.** 같은 낱말이 두 번째 예문에서는 전혀 다른 상황에 나와 뜻이 넓게 잡힌다. 스페인어 시험에서 경찰서·가족, 병원·성처럼 짝지은 것이 이 꼴이다.
- 같은 무대는 언어 안에서 연달아 쓰지 않는다(plan.ts가 최근 5묶음 무대를 피함).

### 인물
- 언어마다 흔한 이름 목록(`settings.json` names.<언어>, 남녀 각 30). 묶음마다 주인공 하나씩(A·B 다른 사람).
- 나라·출신을 정해 두지 않는다(QA 10-24 지적 "한국 출신 전제" 피함). 실존 인물·브랜드·정치·종교 다툼은 넣지 않는다.

### 문장 규칙 (모든 언어 공통 — analyze가 검사)
- 문장마다 혼자 읽혀야 한다 — 대명사 대신 이름, 앞 문장을 몰라도 뜻이 통하게.
- 낱말 하나는 이야기마다 한 번씩(두 이야기 = 예문 둘). 한 문장에 낱말은 셋까지.
- 숫자(0-9) 없음. 4단계 100자 이하, 5·6단계 140자 이하.
- 빈칸 꼴은 문장 안에 한 번만.
- 라틴·키릴 글자 언어는 낱말을 문장 맨 앞에 두지 않는다(대문자가 되면 빈칸 실패 — es에서 겪음).
- 민감한 낱말(죽음·범죄·병)은 뉴스·소설·역사처럼 거리를 둔 중립 문장으로.

### 언어별 덧붙임 (`settings.json` rules.<언어>)

| 언어 | 덧붙일 규칙 |
|---|---|
| ko | 동사·형용사는 말하는 꼴(가요·갔어요), 사전형 금지 · 빈칸은 조사 붙은 꼴 그대로 |
| ja | 가나·한자 · 동사 활용꼴 빈칸 · 문장 끝 です/ます와 반말 섞어도 됨 |
| zh | 간체 · 빈칸은 낱말 그대로(띄어쓰기 없음 — 다른 낱말 일부로 겹치면 실패) |
| th | 타이 글자 · 문장부호 거의 없음 → 문장 하나 = 한 줄, 겹침 검사 |
| vi | 여러 음절 낱말은 통째로 빈칸(bí ẩn 속 ẩn 안 됨) |
| hi | 데바나가리 · 동사는 활용꼴, 모음 부호 지우지 않음 |
| ar | 모음 부호 없이 · 문장 dir은 화면이 맡음 |
| ru | 키릴 · 격 변화 꼴 빈칸 |
| fr·it·pt·es | 성수 일치 꼴 빈칸 · 문장 첫 낱말 금지 |
| id | 접사 붙은 꼴(me-/di-/-kan) 빈칸 가능 |

### 파일 꼴
`scripts/story/<언어>/<단계><번호>-<무대A>-<무대B>.tsv`
- 줄 형식: `이야기(A|B)\t문장\ten\tko\t낱말=꼴;…`
- 지금 es 파일과 같고, 이야기 글자는 파일마다 A·B로 둔다(언어 전체에 이어 붙는 글자는 안 씀).
- 이야기 원본을 남겨 두면, 나중에 읽기 자료로 쓸지 정할 때 그대로 쓸 수 있다(결정 대기).

## 4. 쓰는 쪽 한 묶음 흐름

```
node --experimental-strip-types scripts/story/plan.ts <언어> --next        # 맡음 표시 + 낱말 40·무대 둘·이름·규칙 출력
(이야기 둘을 scripts/story/<언어>/<파일>.tsv 로)
node --experimental-strip-types scripts/story/analyze.ts <언어> <파일>     # 빈칸 실패 0 · 낱말마다 예문 둘 확인
node --experimental-strip-types scripts/word-sentences.ts --merge <언어> tmp/story/<이름>.merge.json --src story
node --experimental-strip-types scripts/story/plan.ts <언어> --done <묶음>
(5묶음마다) npm run test:curriculum → git add … → commit "낱말 예문 <언어> +N(이야기)" → pull --rebase → push
```

## 5. 보는 쪽

- 커밋마다 언어별 20줄 표본(`plan.ts <언어> --sample 20`, 아직 안 본 묶음에서).
- 볼 것:
  - 원어민이 실제로 하는 말인가
  - en·ko 번역이 맞나
  - 빈칸 꼴이 너무 흔한 꼴이라 답이 새지 않나
  - 같은 문형이 되풀이되지 않나
- 고칠 줄은 `tmp/story/fix/<언어>.tsv`로 낸다. 모으는 쪽이 `--merge --replace`로 갈아 넣는다.
- 한 묶음에서 5줄 넘게 걸리면 그 묶음을 다시 쓰게 돌려보낸다.
- **원어민 확인은 없다** — 에이전트끼리 교차로 보는 것까지다. 출시 전 원어민 표본 확인을 할지는 사용자 결정.
