# 체크로 시작하고, 쌓인 데이터를 튜터가 계속 반영하기 (초안, 2026-10-16)

> 사용자 요청: (1) 처음 지도를 글이 아니라 체크로 만들기 — 상황을 한정하지 말고 "어디가 부족한지, 어떤 부분 위주로 하고 싶은지"로.
> (2) 계속 쌓이는 데이터를 종합해 튜터 프롬프트에 자동으로 반영하기.
> `coaching-loop.md`(대화 중심 개편)의 연장: 체크 = 첫 재료, 대화가 쌓이면 측정값이 이어받음, 튜터와 "오늘 해볼 것"이 같은 요약을 본다.
> 상태: 설계안. 사용자 확인 후 구현.

```
처음 체크 ──► 학습자 요약(learner brief) ◄── 대화에서 쌓이는 것(장부·실수 종류·막힘·해석 열람)
                  │
       ┌──────────┼──────────────┐
       ▼          ▼              ▼
   지도 생성   튜터 프롬프트   오늘 해볼 것
```

## 1. 체크로 시작하기

### 지금
지도 탭 처음: 목표를 글로 쓰고 수준(초급·중급·고급)을 고름 → 지도 생성(호출 1회). 따로 "부족한 부분" 패널에서 학습 방식
(`LearnerPlan`: 약한 것/넓히기/주제 × 채팅/통화/영상/섞어서)을 고를 수 있음 — 영어 구문 목록 기반이라 다른 언어에선 거의 비어 있음.

### 바꿀 것: 세 질문, 한 화면

**① 어디가 부족한 것 같아요?** (여러 개)

| 체크 | 내부 항목 | 지도에서 | 튜터에게 |
|---|---|---|---|
| 말이 바로 안 나와요 | 말 이어가기 | 짧게 자주 말하는 상황 주제(A) 앞으로 | 질문을 짧고 답하기 쉽게, 한 번에 하나 |
| 문장을 맞게 못 만들겠어요 | 정확도 | 표현·문법(B) 비중 ↑ | 그 실수가 나올 만한 질문을 가끔 |
| 단어·표현이 부족해요 | 표현 폭 | 어휘(C) 비중 ↑ | 새 표현을 한 턴에 하나씩 섞기 |
| 말이 빠르면 못 알아들어요 | 알아듣기 | 발음·듣기(D) 비중 ↑, 영상 활동 | 더 쉬운 단어·짧은 문장 |
| 발음이 걱정돼요 | 발음 | D칸 발음 주제, 통화 활동 | (통화의 "다시 말해보기"를 권하기에서 앞으로) |
| 맞긴 한데 어색한 것 같아요 | 자연스러움 | B칸 자연스러운 표현 주제 | 교정의 natural(더 자연스러운 말)을 늘 채우기 |

**② 어떤 걸 위주로 하고 싶어요?** (하나 또는 둘) 말하기 · 듣기 · 쓰기 · 어휘 늘리기
→ 지금의 `LearnerPlan.method`를 대신함(말하기=통화, 쓰기=채팅, 듣기=영상, 어휘=섞어서+단어장).

**③ (선택) 주로 어디서 쓸 것 같아요?** 일상 대화 · 여행 · 일 · 영상·드라마 — 건너뛰면 일상. 상황 주제의 소재.

아래에 "직접 쓰기"(지금의 목표 입력칸)는 그대로 남김. 수준 고르기 칸은 없앰 — 첫 지도는 초급~중급 사이로 그리고,
권하기·튜터는 측정값으로 맞춘다(레벨은 보여주지 않는다는 원칙 그대로).

### 데이터

- 언어별 `selfCheck`: `{ gaps: GapId[], focus: SkillId[], use?: UseId, at }` — 학습자 데이터(learnerProfileStore)에 같이 저장, 문장 없음.
- 지도 생성 프롬프트(`curriculum/prompt.ts`): 지금의 FOCUS_RULE·METHOD_RULE 자리에 체크에서 나온 규칙(칸별 비중, 첫 활동 탭, 상황 소재).
  목표 글이 없으면 ③과 ①로 목표 한 줄을 만들어 지도 제목에 씀("여행에서 말이 바로 나오게").
- 문구: 질문 3개 + 체크 14개 정도 × 14개 언어. 고정 목록(호출 없음).
- 지도가 이미 있는 사용자: 그대로 두고, "새 목표"를 누르면 체크 화면으로. "부족한 부분" 패널의 학습 방식 고르기는 체크 화면으로 합침.

## 2. 학습자 요약 → 튜터 프롬프트

### 지금 튜터에게 자동으로 가는 것
- 배운 표현 최대 3개 다시 써 주기(`recyclePrompt`, 채팅·자유 통화).
- "오늘 해볼 것"으로 시작한 대화의 상황·써볼 표현·실수 종류(`practicePrompt`).
- 통화 난이도 다이얼(`roleplay/difficulty.ts`, 1~5)은 한 대화 안에서만 움직이고 다음 대화로 이어지지 않음.

### 바꿀 것: `learner/brief.ts` (순수 함수, 호출 없음)

입력: 장부, 실수 종류 기록, 체크(selfCheck), 최근 2주 턴 측정(통화 응답 지연·도움 받은 수·해석 연 수·교정 붙은 비율).
출력: 튜터에게 붙일 몇 줄 + 화면에 보여줄 항목 목록(같은 근거).

| 신호 | 기준(초안) | 튜터에게 |
|---|---|---|
| 자주 틀리는 실수 종류 | 2주 안 2번 이상, 상위 2개 | 그 실수가 나올 만한 순간을 가끔 만들기. 교정은 지금처럼 따로 |
| 배운 표현 | 숙지 전, 도움 1시간 지난 것 3개 | 자연스러울 때 한 번 (지금 것 흡수) |
| 막힘이 잦음 | 최근 통화에서 도움 받은 턴 비율 ≥ 30% 또는 응답 지연 중앙값 ≥ 4초 | 짧은 질문, 한 번에 하나, 고를 수 있게 묻기 |
| 해석을 자주 엶 | 최근 튜터 줄의 해석 연 비율 ≥ 50% | 쉬운 단어, 짧은 문장, 천천히 |
| 막힘 없이 길게 말함 | 도움 비율 < 10% 그리고 평균 문장 길이 증가 | 조금 더 어려운 표현과 열린 질문 |
| 체크한 부족한 부분·하고 싶은 것 | 측정 데이터가 적을 때(턴 20개 미만)만 강하게 | 그쪽으로 대화를 기울이기 |
| 숙지한 표현 | — | 일부러 다시 꺼내지 않기 |

규칙:
- **선생님이 되지 않는다.** 요약 맨 앞에 "알리지 말고, 퀴즈 내지 말고, 대화 상대로 남을 것"(practicePrompt와 같은 문장).
- **정체 막기:** 쉬워지는 신호와 어려워지는 신호를 둘 다 둠. 한 번에 한 단계만 움직이고, 2주 창으로만 판단.
- **통화 지연:** 요약은 사용자·언어별로 계산해 10분 동안 KV에 두고 다시 씀. 새로 계산할 때도 저장된 숫자만 읽음.
- **길이:** 튜터에게 가는 줄은 최대 6줄(입력 토큰 소폭 증가, 호출 수 그대로).
- **개인정보:** 문장은 저장하지 않음(지금 원칙). 요약은 실수 종류·표현·숫자로만.

필요한 데이터 보강:
- 해석 연 수: 통화·채팅에서 해석을 열 때 숫자만 서버로(이벤트 하나, 앱 빌드 필요). 지금은 기기에만 있음.
- 통화 도움 받은 턴: director가 이미 판단(stuck·tip) → 턴 측정(learnerMetrics)에 `helped` 칸 추가(서버).
- 응답 지연: 통화는 이미 `response_latency_ms`를 보냄(learnerMetrics). 사용자별 2주 집계 함수만 추가.

### 화면: "튜터가 알고 있는 것"

지도 탭 세부(내 표현 옆)에 한 장:
- "과거형을 자주 헷갈려요 · 질문을 짧게 하고 있어요 · 'end up'을 다시 써 주는 중" 같은 줄(UI 언어, 틀 문구)
- 항목마다 끄기, 전체 끄기 스위치(끄면 요약을 튜터에게 안 보냄, 권하기는 그대로)
- 처음 체크 다시 하기

## 3. "오늘 해볼 것"과의 관계

권하기(`learner/next.ts`)도 같은 요약을 읽는다:
- 데이터가 적을 때: 체크한 부족한 부분으로 권함 — "말이 바로 안 나와요" → 짧은 통화, "못 알아들어요" → 해석 끄고 영상 장면, "단어가 부족해요" → 표현 써보기 대화.
- 쌓이면: 지금 순서(자주 틀림 → 안 쓴 배운 표현 → 상황 …) + 막힘·해석 신호로 탭 선택(막힘 잦음 → 채팅 먼저, 길게 말함 → 통화).
- 나중에(coaching-loop 단계 3) 지도 첫 화면: "처음엔 '말이 바로 안 나온다'를 골랐어요 → 지난 2주 막힘 12 → 7"처럼 체크와 측정을 나란히.

## 언어

14개 학습 언어·14개 UI 언어 모두. 요약의 튜터용 줄은 영어(모델이 읽음), 화면 줄은 틀 문구로 UI 언어. 해석 열람·지연은 언어와 무관한 숫자.
띄어쓰기 없는 언어도 "평균 문장 길이"는 글자 수가 아니라 `wordSegments` 단어 수로.

## 단계

1. **학습자 요약 + 튜터 반영(서버만):** `brief.ts`, 지금 있는 신호(실수 종류·배운 표현·통화 응답 지연)로 시작, 채팅·통화 프롬프트에 붙임,
   recyclePrompt 흡수. 바로 반영(빌드 불필요). 운영에서 같은 사용자로 요약 전후 튜터 말 비교.
2. **체크로 시작:** 체크 화면(지도 탭 처음·새 목표), selfCheck 저장, 지도 생성 프롬프트, 권하기의 데이터 적을 때 분기. 앱 빌드 필요.
3. **신호 보강:** 해석 열람 이벤트, 통화 helped, 길게 말함. 앱 빌드 필요(해석 이벤트).
4. **"튜터가 알고 있는 것" 화면과 끄기.** 앱 빌드 필요.

## 사용자에게 정할 것

1. 체크 ① 6개 항목 그대로 갈지(빼거나 더할 것). 추천: 그대로.
2. 수준 고르기를 없앨지. 추천: 없앰(측정으로 맞춤). 직접 쓰기에서도 없앰.
3. 단계 1(서버만, 바로 반영)부터 할지. 추천: 1부터 — 빌드 없이 튜터가 바로 달라짐.
4. "튜터가 알고 있는 것" 화면을 단계 4로 미룰지, 단계 1과 같이 할지. 추천: 미룸(먼저 효과 확인).
