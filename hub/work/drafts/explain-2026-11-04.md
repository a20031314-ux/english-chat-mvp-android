# 표현·문법 설명 — 파일에 넣기 (설계안, 2026-11-04)

> 사용자 2026-11-04: 설명도 써 넣는다. 구성만 정한다.
> 상태: **설계만.** 설명 글은 아직 파일이 없다. 지금 앱은 그 칸을 처음 열 때 서버가 만든다(`itemlesson:v2`, `gramlesson:v1`, `exprcards:v2`). 이 문서를 코드로 만들 때 그 칸은 파일의 글을 먼저 읽고, 없는 열쇠만 예전처럼 만든다.

설명은 Stagebank 설명 칸이다. 퀴즈의 `why`(정답인 이유 한 문장)와 예문 파일의 문장 번역은 설명이 아니다. 둘 다 그대로 둔다.

## 1. 어디에 두나

학습 언어마다 파일 하나. `src/lib/curriculum/explain/<언어>.json`. 열쇠는 예문 파일과 같다. `e|<표현>`, `g|<단계>:<번호>`.

학습 언어로 적는 것(꼴, 틀린 문장, 바른 문장)은 그 언어로 한 번만 둔다. 앱 언어로 읽는 글은 한국어와 영어를 파일에 둔다. 나머지 열두 앱 언어는 단계 글과 같이 서버가 이 파일에서 한 번 옮긴다.

## 2. 문법

화면 순서 그대로다. 규칙, 꼴 표, 예외, 쓰임, 흔한 실수.

| 칸 | 글 | 분량 |
|---|---|---|
| `rule` | 앱 언어. 이 문법이 무엇인지 | 한두 문장. 문법 용어는 이름에 필요할 때만 |
| `forms` | `from`·`to`는 학습 언어. `note`는 앱 언어 | 2~4줄. 화면은 6줄까지 받는다 |
| `exceptions` | 앱 언어 | 한 줄. 없으면 칸을 뺀다 |
| `usage` | 앱 언어. 원어민이 언제 이 꼴을 고르나 | 한 문장 |
| `mistakes` | `wrong`·`right`는 학습 언어. `why`는 앱 언어 | 두 개 |

꼴이 바뀌지 않는 문법(어순, 관사)은 표의 `from`을 자리, `to`를 그 자리에 들어가는 꼴로 둔다. 활용표가 아니다.

흔한 실수의 `wrong`은 그 문법의 깨진 꼴이다. 다른 문법의 맞는 문장을 오답으로 두지 않는다. `why`는 바른 꼴이 바른 이유를 한 문장으로 말한다.

```json
"g|1:0": {
  "rule": { "ko": "하나면 is, 여러 개면 are, 나는 am이다.", "en": "One thing takes is, more than one takes are, and I takes am." },
  "forms": [
    { "from": "I", "to": "am", "note": { "ko": "말하는 사람", "en": "the speaker" } },
    { "from": "he / she", "to": "is", "note": { "ko": "하나", "en": "one" } },
    { "from": "you / they", "to": "are", "note": { "ko": "상대, 또는 여럿", "en": "you, or more than one" } }
  ],
  "usage": { "ko": "누구인지, 무엇인지, 어디에 있는지를 말할 때 쓴다.", "en": "You use it to say who someone is, what something is, or where it is." },
  "mistakes": [
    { "wrong": "She am a nurse.", "right": "She is a nurse.", "why": { "ko": "she는 하나라서 is다.", "en": "She is one person, so the form is is." } },
    { "wrong": "They is here.", "right": "They are here.", "why": { "ko": "they는 여럿이라서 are다.", "en": "They is more than one, so the form is are." } }
  ]
}
```

## 3. 표현

표현 카드에 보이는 것은 뜻과 예문이다. 예문은 예문 파일의 첫 문장을 쓴다. 설명 파일에 예문을 다시 쓰지 않는다. 뜻은 그 표현의 짧은 뜻이다. 문장 전체의 번역이 아니고, 표현을 그대로 베끼지 않는다.

| 칸 | 글 | 분량 |
|---|---|---|
| `gloss` | 앱 언어. 표현의 뜻 | 짧은 말 하나 |
| `usage` | 앱 언어. 언제 쓰나 | 한 문장 |
| `contrast` | 앱 언어. 비슷한 표현과 어디가 다른지 | 한 문장. 헷갈릴 짝이 없으면 칸을 뺀다 |

수업의 대화 단계는 예문 파일의 문장을 내 줄로 쓴다. 상대 줄은 비운다. 설명 파일에 대화를 다시 쓰지 않는다.

```json
"e|have a nice day": {
  "gloss": { "ko": "좋은 하루 보내세요", "en": "a goodbye that wishes someone a good day" },
  "usage": { "ko": "헤어질 때 쓴다.", "en": "You say it when you part." }
}
```

## 4. 퀴즈와 나누는 곳

퀴즈 문제의 `why`는 그 보기가 정답인 이유 한 문장이다. 설명의 `rule`을 퀴즈에 붙이지 않고, 퀴즈 `why`를 설명 칸에 붙이지 않는다. 설명의 실수 문장을 퀴즈 보기로 그대로 베끼지 않는다.

## 5. 만들 때

한 언어 파일에 그 언어의 표현·문법을 모두 넣는다. 영어가 먼저다. 예문 열쇠가 없는 설명은 만들지 않는다. 이미 있는 예문 문장은 고치지 않는다.

앱에 넣기 전에는 열쇠가 단계 목록과 맞고, 한국어·영어가 비어 있지 않은지, 꼴 표가 2~4줄인지, 실수가 두 개이고 틀린 문장과 바른 문장이 다른지 확인한다.
