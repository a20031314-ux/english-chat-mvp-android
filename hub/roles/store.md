# 스토어·출시

## 맡는 일
- 버전 올리기 (`package.json` version ↔ `build.gradle` versionCode/versionName).
- 출시 노트와 등록정보 14개 언어 — `store-listing` 스킬, `fastlane/metadata/android/`.
- 스토어 스크린샷 — `store-shots/` (고정 AI 응답으로 실제 앱을 찍음).
  사용자 결정(2026-10-18): 스크린샷 한 장에 기능 하나일 필요는 없다. 한 탭의 여러 기능을 한 장에 묶어도 된다
  (예: 채팅 = 교정 + 표현 카드 + 빠른 질문). Play 8장 한도 안에서 탭을 더 넓게 보여주는 쪽을 우선.
  홍보 쇼츠는 반대로 한 편에 기능 하나만, 15초 안팎, 영어판을 먼저 만들고 다른 언어로 넓힌다(사용자 결정 2026-10-19). `store-shots/promo/`.
  목소리 대화판(`make.mjs talk <locale>`, Room 녹화 재사용): 사람마다 다른 TTS 목소리, 세부 기능은 확대 창으로 띄움(사용자 요청 2026-10-19).
  흐름은 기능마다 "내레이터 설명(UI 언어, 화면 멈춤) → 실제 대화"(사용자 요청 2026-10-19). 약 50초.
  홍보 계획·시리즈·언어판(2026-10-24): `hub/drafts/marketing-videos.md` — AI 학습(채팅·분석·오류교정·통화) / 사용자 간(단체방), 언어판 8개는 `store-shots/promo/combos.mjs`.
- 앱 안 업데이트 배너 기준 `RECOMMENDED_APP_VERSION` — Play에 실제로 공개된 뒤에만 올린다.
- 사용자가 PC에서 빌드할 때 막히면 돕는다 (`npm run build:android` → Sync → Signed Bundle).

- 등록정보(설명·제목 14개 언어, 기본 스크린샷 8장 en·ko·ja·zh·es·hi)는 저장소가 원본(2026-10-21 업로드 성공). 서비스 계정 권한 생김 — 병합하면 바로 올라감. "Store: screenshots"(v* 태그)의 옛 3장 PR은 병합 금지.

## 하지 않는 일
- fastlane 실행, Play API 호출, 서명 키 읽기, 프로덕션 워크플로 실행 — 막혀 있고, 사람이 한다.
- 기능 코드 수정 (→ dev).

## 시작할 때
1. `git pull`, `inbox.md`에서 `→ store` 항목 확인 (출시할 변경이 무엇인지). 문구·스크린샷은 `PRODUCT.md` 기준.
2. 아래 "출시 기록"의 마지막 버전과 `build.gradle`을 맞춰 본다.

## 끝낼 때
- 버전이 바뀌면 `hub/STATE.md`의 버전 표와 `PRODUCT.md`의 "기준"·"버전별 변화"도 같이 고친다.
- 이 파일과 `hub/log/YYYY-MM.md` 한 항목을 같이 커밋.

## 열린 일
- **홍보 쇼츠 (2026-10-24, `hub/drafts/marketing-videos.md`):** 오류교정 편(`record-fix.mjs` → `make.mjs fix`) 8개 판 모두 사용 가능(한·일 교정 표시 버그는 dev가 고침 2026-10-24, 앱은 다음 빌드 — 영상은 고친 웹 빌드로 찍음). 다음: 분석·통화·단체방 편, 채팅 편을 새 조합·지금 화면으로 다시, 옛 room·people·talk 편은 💡 힌트(10-23 뺌)가 나와 쓰지 않음. 2.72 공개 뒤 다시 찍기. 채널(언어별)·올리기 버튼은 사람이 채널 만든 뒤.
- **iOS 운영 방향(사용자 2026-10-22, `hub/drafts/ios-ops-2026-10-22.md`):** 기간 없이 — AI 학습은 안드로이드와 같게(AI 학습이 바뀐 안드로이드 버전은 같은 버전을 iOS에도), 사람 기능은 안드로이드에서 안정 기준(문서 1절 5가지)을 넘으면 iOS에. 랜덤 연결은 iOS에 안 넣음.
- **iOS 1차 (2026-10-18, `hub/drafts/ios-launch.md`):** 코드 준비 끝(`ios/`, 방·메시지·Google 로그인 없음). 사용자: 아이폰·개발자 계정 있음, 빌드는 클라우드.
  `.github/workflows/ios-testflight.yml`(사람이 누름, API 키 클라우드 서명 → TestFlight) 있음 — 사람이 "클라우드 빌드 설정" 8단계(번들 ID·App ID·앱·API 키·팀 ID·GitHub environment `ios`) 뒤 첫 실행.
