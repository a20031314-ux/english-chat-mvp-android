# 기능 개발

## 맡는 일
- 앱 화면·흐름·서버 API 기능을 만들고 고친다. main에 push하면 서버가 바로 배포된다.
- 새 화면 문구는 14개 언어로 넣는다 (AGENTS.md "Language combinations" 1번).
- 기능이 앱에 들어가는 출시면 `src/lib/whatsNew.ts`에 안내 항목을 추가하고
  `scripts/capture-whats-new.mjs <버전>`으로 캡처를 만든다.

## 하지 않는 일
- Play 등록정보·출시 노트 (→ store), 버전 올리기와 배너 기준 (→ store, 요청받으면 같이).
- 점검에서 나온 문제를 혼자 판단해 고치기 시작하지 않는다. inbox로 받은 것만, 또는 사용자가 고르라고 한 것만.

## 시작할 때
1. `git pull`, `inbox.md`에서 `→ dev` 항목 확인. 만들 기능이 `PRODUCT.md` 핵심 가치에 맞는지 본다.
2. 아래 "열린 일"과 사용자의 요청을 맞춰 본다.

## 끝낼 때
- 커밋에 이 파일(열린 일 갱신)과 `hub/log/YYYY-MM.md` 한 항목을 같이 넣는다.
- 화면·기능·한도가 바뀌었으면 `PRODUCT.md`도 같은 커밋에서 고친다.
- 출시가 필요한 변경이면 `inbox.md`에 `dev → store` 한 줄.
- 화면이 바뀌었으면 `inbox.md`에 `dev → qa` 한 줄 (무엇을 어떤 언어 조합으로 볼지).

## 열린 일
- 통화 "이렇게 말하려던 거죠?"(meant)는 main에 있음(84de02a 외). 서버(튜터 판단·받아쓰기 그대로 적기)는 배포됨,
  카드는 2.65 빌드부터(2.64는 같은 문장을 "이렇게 말할 수 있어요"로 받음). 다음: 채팅에도 같은 되살리기.
- 표현의 세 상태(숙지·배운 것·알아야 할 것)와 복습은 main에 있음(84cf387 외). 숙지 = 도움 없이 꺼내 씀(첫 시도 무힌트 통과,
  또는 마지막 시도 8시간 뒤 복습·채팅·통화에서 맞게 씀). 8시간 뒤 복습 화면은 실제 시간이 지나야 확인 가능(단위 테스트로만 확인).
- 사용법(?)의 지도 안내(`src/lib/guide/content.ts` + translations.json)가 미션 이전 내용(연습 = 탭 바로가기, 직접 완료 표시).
  "할 일로 연습하기"와 자동 완료로 14개 언어 고쳐야 함.
- 지도 주제 미션(할 일 → 써보기 → 확인·교정, 힌트 3단계, 자동 진행률)은 main에 있음(64f9cd6 외).
  서버는 배포됨, 화면은 2.65 빌드부터. 다음 단계: 통화 학습에서 같은 미션으로 말하기, 2.65 "새로워진 점" 항목과
  캡처(`scripts/capture-whats-new.mjs`에 미션 화면 단계 추가 필요).
- 통화 학습: 말 끊김(문장 중간 멈춤) 대기와 노트 오역 수정은 main에 있음(f3fd4da). 서버 쪽(노트 걸러내기, 튜터 지시)은
  이미 배포됨, 앱 쪽(이어 말하기 대기, 점선 말풍선)은 2.65 빌드부터. 기기 확인 결과 대기.
- 학습지도 칸 번호가 `A1 · 1`처럼 보여 수준 표시로 오해될 수 있음. 바꿀지 사용자 결정 대기.
  바꾸면 2.64 안내 캡처(`public/whats-new/2.64/*/map.webp`)도 다시 찍어야 함.
- 사용자에게 제안만 하고 아직 요청받지 않은 것:
  튜터가 학습한 표현을 다시 써 주기 / 해석 버튼을 이해도 데이터에 연결 /
  구문 추천을 채팅 시작 문장으로 연결.

## 참고
- 로컬 확인: `npm run build:capacitor` 후 www를 띄우고 /api는 운영 서버로 프록시
  (`scripts/browser-language-pass.mjs`가 같은 방식).
- 웹에서는 YouTube 음성 추출이 막혀 영상 준비가 NO_AUDIO로 실패한다. 영상은 기기에서만 확인 가능.
