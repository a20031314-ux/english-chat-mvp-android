# 기능 개발

## 맡는 일
- 앱 화면·흐름·서버 API 기능을 만들고 고친다. main에 push하면 서버가 바로 배포된다.
- 새 화면 문구는 14개 언어로 넣는다 (AGENTS.md "Language combinations" 1번).
- 기능이 앱에 들어가는 출시면 `src/lib/whatsNew.ts`에 안내 항목을 추가하고
  `scripts/capture-whats-new.mjs <버전>`으로 캡처를 만든다.

## 하지 않는 일
- Play 등록정보·출시 노트 (→ store), 버전 올리기와 배너 기준 (→ store, 요청받으면 같이).
- 점검에서 나온 문제를 혼자 판단해 고치기 시작하지 않는다. inbox로 받은 것만, 또는 사용자가 고르라고 한 것만.

## 시작할 때
1. `git pull`, `inbox.md`에서 `→ dev` 항목 확인. 만들 기능이 `PRODUCT.md` 핵심 가치에 맞는지 본다.
2. 아래 "열린 일"과 사용자의 요청을 맞춰 본다.

## 끝낼 때
- 커밋에 이 파일(열린 일 갱신)과 `hub/log/YYYY-MM.md` 한 항목을 같이 넣는다.
- 화면·기능·한도가 바뀌었으면 `PRODUCT.md`도 같은 커밋에서 고친다.
- 출시가 필요한 변경이면 `inbox.md`에 `dev → store` 한 줄.
- 화면이 바뀌었으면 `inbox.md`에 `dev → qa` 한 줄 (무엇을 어떤 언어 조합으로 볼지).

  2주 안 2번이면 미션 추가)는 배포됨, 화면(칩·순서·"자주 틀리는 부분" 표시)은 2.65 빌드부터. 지도 위 "부족한 부분" 패널은
  영어 구문 목록 기반이라 다른 언어에서는 여전히 "아직 데이터가 없어요" — 이 실수 기록을 패널에도 보여줄지 결정 필요.
