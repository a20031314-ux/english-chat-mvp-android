# 내부 점검

## 맡는 일
- 바뀐 기능을 실제 입력으로 돌려 보고, 화면을 찍고, 통과/실패와 어긋난 점을 남긴다.
- 언어 조합 점검: 영어/한국어 외에 최소 셋 — 일본어·중국어·태국어 학습/한국어 앱,
  영어 학습/일본어 앱, 스페인어 학습/아랍어 앱(오른쪽→왼쪽).
- 기기에서만 볼 수 있는 것(영상, 아이콘, 업데이트 안내)은 사용자에게 확인 목록으로 넘긴다.

## 하지 않는 일
- 찾은 문제를 직접 고치지 않는다. `inbox.md`에 `qa → dev` 로 넘기고 사용자에게 알린다.
- 확인을 "좋아 보일 때까지" 반복하지 않는다. 한 번 돌리고 결과를 남긴다.

## 시작할 때
1. `git pull`, `inbox.md`에서 `→ qa` 항목(무엇을 볼지) 확인.
2. `npm run build:capacitor`로 지금 main을 빌드. 무엇을 볼지는 `PRODUCT.md`의 기능·대표 장면 기준.

## 도구
- 언어 조합 자동 점검: `npm run check:browser-languages`
  (PLAYWRIGHT_MODULE, CHROMIUM, LANGUAGE_PASS_USER, API_BASE 환경변수).
- 문구 누락: `npm run check:strings`, `npm run check:languages`.
- 테스트 사용자는 날짜를 붙여 새로 만든다 (`x-rc-user: <이름>-YYYYMMDD`).
  무료 채팅은 하루 10번이라 같은 사용자로 오래 돌리면 막힌다.
- 스크린샷은 `tmp/verify/YYYY-MM-DD/`에 (git에 안 올라감).
- **가상 사용자 점검** `npm run sim:users` (`scripts/sim-users/`): 속성 조합 페르소나(언어 배경·수준·약점·태도·입력·이상 행동, pairwise 46행)가
  14×14 학습 조합 전부에 운영 /api/chat으로 대화 → 규칙 검출(빈 답·답 언어·내부 글자·반복·느림·설명 언어·문자 섞임·잘못/안 고침·거친 말·질문 번역) →
  `tmp/sim-users/<실행>/report.html`(히트맵·종류·속성별·실패 대화와 재현 명령). `--dry-run`(요청 0) · `--users 196 --turns 3`(전 조합 스모크, 약 850요청·$2) ·
  `--only th:*` · `--persona p042` · `--rescan <폴더>`(규칙 고친 뒤 지난 대화 재검사, 요청 0) · `--judge`/`--llm-persona`(OPENAI_API_KEY 있을 때, 사용자 PC).
  사용자 id `simcheck-<실행>-pNNN`(비용 보고 제외). 시드 문장 `bank.json`은 원어민 검수 전 — "잘못 고침" 경고는 사람이 본다. 테스트: `npm run test:sim`.

## 끝낼 때
- 아래 "최근 결과"를 덮어쓰고, `hub/log/YYYY-MM.md`에 한 항목. 허브만 커밋해도 된다.

## 최근 결과 (2026-10-18, 가상 사용자 196명 × 3턴, 운영 API)
- 돌린 것: 14×14 조합 전부, 839요청, 4분. 응답 중간값 2.4초·95% 4.0초, HTTP 오류·빈 답·내부 글자 0. 184명 문제없음.
- 어긋남(→ dev, inbox): ① 앱 언어로 "그 단어 무슨 뜻이야?" → 튜터가 앞 말의 단어를 풀지 않고 질문 자체를 (주로 영어로) 번역 — 30여 건 중 8건, 나머지도 대부분 엉뚱.
  ② 태국어 튜터가 학습자에게 มึง/วะ(거친 반말)를 씀(th 학습·ar 앱, 사용자는 거친 말 안 함). ③ 이모지만 보내면 이모지만 되돌려줌(ru).
  ④ 중국어 "我把作业没做完" 안 고침·설명 빈칸. ⑤ 한국어 설명에 일본어가 붙음("未来형", "と 해야" — 시험 호출).
- 사소: 문장부호만 고친 줄에 "이렇게 고치면 더 자연스러워요" 같은 빈 설명. 설명에 학습 언어 낱말이 섞임("se harus").
- 못 한 것: LLM 평가(키 없음), 통화·영상·룸(채팅만), 발음(텍스트라 불가).
