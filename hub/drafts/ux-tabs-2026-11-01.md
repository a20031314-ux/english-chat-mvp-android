## 2. 인물 = 사람 카드 (`scripts/ux-check/personas.json`)

한 줄 소개 대신 행동을 정하는 칸. 칸 이름은 `sim-users/personas.mjs` ATTRIBUTES를 그대로 써서 두 도구가 같은 말을 쓴다.

| 칸 | 뜻 | 쓰이는 곳 |
|---|---|---|
| 언어 | 학습 언어 · 앱 언어 | 언어 조합 규칙(AGENTS.md) |
| 삶 | 나이·일·하루 쓸 시간 | 얼마나 오래 누르다 그만두나 |

| 실력 | 단계 0~5 + 실제로 할 수 있는 말 예시 셋 | 퀴즈·대화에서 실력대로 답하기 |
| 자주 틀리는 것(weakness) | 시제·일치·조사·어순·철자·어휘·말투 중 1~2 + 실제 틀린 문장 예 | **AI 대화에 실수를 심는 재료**(4절) |
| 성격(temperament) | 보통·단답형·수다형·막히면 모국어·질문 많음·같은 실수 반복 | 채팅·통화 말투 |

## 3. 탭 미션 모듈 (`scripts/ux-check/tabs/<줄>.md`)

인물에게 주는 BRIEF는 공통 부분(조작·기록·마지막 보고) + **그 줄의 모듈 하나**. 모듈마다 같은 다섯 칸: 들어가는 길 · 중립 과제(문제를 알려 주지 않음) · 점수 칸 · 표시 코드 · 남길 증거.

### my — Stagebank · Quizbank · Logbank

- **과제:** 오늘 할 것 끝까지 → Quizbank 탭마다 한 묶음 → (`/day`) 어제 한 일을 Logbank에서 찾아 말하기 → 단계 화면에서 "다음 단계까지 뭐가 남았는지" 말하기.
- **점수:** 지금 6칸 그대로(명확·계속·향상·쉬움·효과·적용).
- **표시:** 지금 퀴즈 코드 9개 + `stuck-next`(다음에 뭘 할지 모름) · `progress-mismatch`(숫자·점이 서로 엇갈림).

### ai — AI 대화 · AI 통화 · 영상 학습

- **과제:** AI 대화 8~10줄(자기 weakness대로 실수를 섞어서, 성격대로) → 고친 말 하나를 문장분석으로 열기 → AI 통화 6~10턴(`/say`), 막히면 💡 → 통화 끝 화면이 가리키는 다음 공부를 따라가기 → 이달의 영상 문장 하나 분석.
- **점수(6칸):**
  1. 교정이 맞고 도움이 되나(심은 실수 대조로 숫자도 같이 — 4절)
  2. 튜터가 내 수준에 맞게 말하나(너무 어렵거나 쉬우면 감점)
  3. 대화가 이어지나(끊긴 답·맥락이 틀린 답)
  4. 막혔을 때 도움이 되나(💡·편한 말로 쓰기·표현 보기)
  5. 끝나고 다음 공부로 이어지나(통화 정리 → My)
  6. My에서 배운 문장구조를 대화에서 써 봤나
- **표시:** `fix-missed`(틀렸는데 안 고침) · `fix-over`(맞는데 고침) · `fix-wrong`(고친 것도 틀림) · `explain-off`(설명이 다른 줄 이야기거나 앱 언어가 아님) · `reply-level` · `reply-break`(끊김·맥락) · `slow`(답이 늦음 — 도구가 시간을 잼) · `hint-useless` · `recap-useless`.

### people — 대화(1:1·단체방) · 사람 · Room

- **과제(둘이 한 판, 민지 + Emma):** 각자 숨김 임시 계정으로 로그인한 앱(5절) → 게시판 메이트 글·초대 링크로 서로 찾기 → 메이트 신청·수락 → 1:1 메시지 5줄씩 주고받기(교정·번역·분석 한 번씩) → 한 사람이 Room을 열고 다른 사람이 들어와 몇 마디 → 차단·신고가 어디 있는지 찾기만(누르지 않음).
- **점수(5칸):** 상대를 찾을 수 있나 · 첫 말 걸기가 쉬운가 · 대화하면서 배우는가(교정·번역·분석) · 안전하다고 느끼나(차단·신고가 보이나) · 다시 만날 이유가 있나.
- **표시:** `no-partner` · `first-step`(무엇을 눌러야 말을 거는지 모름) · `hidden-sheet`(눌렀는데 안 뜸 — RULES 층 규칙) · `fix-*`(방·DM 교정, ai와 같은 코드) · `safety-missing` · `lang-pair`(언어 쌍이 안 맞는 사람만 보임).
- **판단에서 뺄 것:** 실제 사람이 없는 시간대의 빈 방·빈 목록(숨김 계정이라 목록에 안 뜸) — 운영 숫자로 본다.

### 공통 표시(모든 줄)

`text-heavy`(설명 글이 화면에) · `name-clash`(같은 기능 다른 이름, 다른 기능 같은 이름) · `dead-end`(돌아갈 길 없음) · `lang-mix`(앱 언어 아닌 말이 설명에).

## 4. 도구에 더할 것

- **문제째 남기기를 모든 탭으로:** 퀴즈의 `data-quiz-meta`처럼, 탭마다 점검용 속성 `data-ux-meta`(화면에 안 보임)를 단다 — AI 대화 줄(내 말·고친 말·설명·튜터 답·걸린 시간), 통화 턴, DM·방 줄. 각 meta에 `lane`. `/mark`는 화면에 보이는 `[data-ux-meta]`·`[data-quiz-meta]`를 다 담는다. 점검은 웹 빌드(`build:capacitor`)로 돌아서 **앱 출시 없이 바로** 쓸 수 있다.
- **심은 실수 `/plant`:** 인물이 보내기 전에 `/plant {"text":"I go there yesterday","errors":["시제: go → went"]}`. driver가 다음 내 줄 meta(고친 말·설명)와 묶어 둔다. 점검이 끝나면 **인물과 다른 판정 에이전트**가 `sim-users/judge-rubric.md` 기준(right · missed · overcorrected · partial · wrong, 설명 일치, 앱 언어)으로 판정 → 줄별 교정 숫자.
- **답 걸린 시간:** driver가 보낸 시각부터 튜터 줄이 생긴 시각까지를 meta에 → `slow` 판정과 평균.
- **사람 탭 로그인:** `sim-users/accounts.mjs`(숨김 임시 계정, 끝나면 삭제 — 이미 운영에서 쓰는 방식)로 driver가 로그인한 채 시작. BRIEF의 "로그인하지 마세요"는 people 모듈에서만 "이미 로그인돼 있음"으로 바꾼다. 결제는 여전히 금지.
- **triage 줄별:** 표시의 meta `lane`(없으면 화면 → 영역 → 줄)로 나눠 `hub/drafts/ux-marks-<날>-<줄>.md`. 고칠 자리 표를 줄마다:
  - ai: `fix-*` → `src/app/api/chat` 교정 지시·`lib/correction*` · 통화 `server/turn.ts` · 💡 `lib/roleplay/review.ts` · 정리 `lib/roleplay/recap.ts`
  - people: `fix-*` → `server/roomFix.ts` · `hidden-sheet` → 그 시트의 `above`/층 · 나머지 `components/rooms/*`
  - my: 지금 표 그대로

## 5. 점검 채팅 하나가 돌리는 순서

1. 차례가 "점검"인 줄을 모은다(`hub/lanes/<줄>.md`, 줄 체계 전에는 사용자가 말한 줄).
2. `npm run build:capacitor` 한 번 → 인물마다 driver 하나(people은 짝 둘, 로그인한 채).
3. 인물마다 **줄 모듈별로 에이전트를 따로** 띄운다. 같은 driver·같은 사용자라 앱 기록은 이어지고, 에이전트의 생각은 그 탭에 집중한다.
   - 1일째: 공통 첫 10분(처음 설치 — 지금처럼) → 그 줄 모듈
   - `/day 3` → 3일째 그 줄 모듈 짧게, `/day 11` → 14일째 짧게
4. 끝나면 판정 에이전트 둘(인물과 다른): ① 심은 실수 대조(ai·people) ② `ux-issues.md` 판정(지금 JUDGE.md).
5. triage 줄별 → 보고서 `hub/drafts/ux-check-<날>.md`는 **줄마다 한 절**(그 줄 점수 표·지난번 비교·막힌 화면·표시 수) → 그 줄의 받은 일로 넘김(`hub/lanes/<줄>.md` "라운드 n 결과" + 차례: 개발).
6. 난이도 표시를 바로 고치는 예외는 줄 채팅이 받아서 고친다(lanes 설계 "정할 것 3").

한 줄만 점검하는 라운드는 지금(앱 전체를 셋이)보다 짧다. 세 줄을 한 번에 보면 인물 넷 × 모듈 최대 셋.

## 6. 만드는 순서 (고르면 이대로)

1. `personas.json`(인물 넷) + BRIEF를 공통 + `tabs/{my,ai,people}.md`로 나눔.
2. driver: `/mark`가 `[data-ux-meta]`까지 담기, `/plant`, 답 걸린 시간, 로그인 시작(`UX_ACCOUNT`).
3. 앱에 `data-ux-meta` — AI 대화·통화 턴·DM·방 줄(점검용, 화면에 안 보임).
4. triage 줄별 + 고칠 자리 표, 심은 실수 판정 단계(`PLANT.md`, judge-rubric 재사용).
5. RULES "사용자 체감 점검" 절을 줄별 점수 표로, BRIEF 예전 점수 6칸은 my 모듈로.
6. 시범: ai 줄 한 라운드(민지·준호·Layla) → 결과를 보고 칸·코드 조정.

## 7. 정할 것

1. **Emma 같은 상대역 인물**을 두고, 사람 탭 점검에서 운영에 숨김 임시 계정을 만들었다 지워도 되는지(sim-users가 이미 하는 방식).
2. 심은 실수 판정 비용 — 인물당 대화·통화 20줄 안팎을 판정 에이전트가 봄(모델 호출은 점검 채팅 안에서만, 앱 비용 아님).
3. `data-ux-meta`를 앱 코드에 넣는 일을 **점검 채팅이 한 번에** 할지(제안: 점검 도구용이라 점검 채팅 — 줄 경계 예외), 줄 채팅이 나눠 할지.
4. 시범을 ai 줄부터 할지(제안: 지금 피드백이 가장 적은 줄).
