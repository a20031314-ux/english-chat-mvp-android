# 광고로 무료 사용 늘리기 — 설계안 (2026-10-18)

> 사용자: "광고 수익이 가능하면 무료 이용자의 기능 사용을 확대" → "손익분기점이 양수가 되는 만큼 광고를 넣고 풀어주되 구독하면 광고 없음"
> → "채팅 n회·특정 기능 뒤에 띄우기". **구현함(2026-10-20)** — 서버 반영, 앱은 다음 빌드. 처리방침 고침. 아래 "넣는 순서"의 사람 할 일 중 SSV URL·Play 신고가 남음.
> 숫자는 `hub/costs.md`(자동 계산) 단가와 한국 AdMob eCPM 대략값(보상형 $8~20, 전면 $3~10, 1달러 1,400원)으로 잡은 추정.

## 지금 상태 (저장소 확인)

- 앱에 광고 코드 없음. 무료 = 채팅 하루 10번(`FREE_DAILY_CHAT_LIMIT`), 오늘의 팩 1번, 통화는 처음 한 번 20포인트(약 100분)뿐.
- 한도는 서버가 KV로 셈(`entitlementStore.ts` `getDailyUsed`·`incrementDailyOpUsed`, 요금표 `billing/plans.ts`).
- **광고를 넣으면 바뀌어야 하는 약속:** 처리방침에 "광고에 사용하지 않음"(`src/app/privacy/page.tsx` ko 200줄·en 83줄),
  Play 데이터 보안·"광고 ID 안 씀" 신고(`capacitor.config.ts` 주석). Play 등록정보에 "광고 포함" 표시도 붙음.

## 광고 1회의 값 vs 주는 것의 원가

| 주는 것 | 원가 | 보상형 1회 11~28원 | 전면 1회 4~14원 |
|---|---|---|---|
| 채팅 1번 | 2원 | — | 채팅 3~4번당 1회가 본전 근처 |
| 채팅 5번 | 10원 | 남음 (가장 안전) | 낮은 날 손해 |
| 오늘의 팩 1번 더 | 14.2원 | 낮은 날 거의 본전 | 손해 |
| 자유 통화 1분 | 11원 | 본전 근처 — 2분부터 손해 | 손해 |
| 포인트 1개 | 55.2원 | 손해 (주지 않음) | 손해 |

무료 사용자의 지금 최악 비용은 한 달 1,031원(팩 426 + 채팅 605).

## 정한 방향: 전면(자연스러운 끝) + 보상형(더 쓰고 싶을 때) + 구독자는 광고 없음

1. **여유 두기:** 풀어주는 양의 원가 ≤ 광고 수익의 60~70%. 단가는 달마다 바뀜(연말 높고 1월 낮음) — 딱 본전이면 낮은 달에 적자.
2. **비율은 서버 설정:** "광고 1회 = 채팅 몇 번", 전면 광고 간격, 하루 상한을 서버 값으로 → 앱 빌드 없이 조정. 처음엔 보수적으로, AdMob 실수익 + `cost-report.mjs` 실측으로 매주.
3. **전면 광고는 자연스러운 끝에만:** 통화 끝 → 돌아보기로 넘어갈 때, 오늘의 팩 마침, 미션 하나 끝, 채팅 몇 번 주고받은 뒤 화면을 나갈 때.
   금지: 통화 중·튜터 답 기다리는 중·쓰는 중·누르려는 순간·앱 열자마자(흐름 끊김, Play 정책). 몇 분에 1회 이하.
   이 수익만큼 무료 채팅을 넓힘(채팅 3~4번당 전면 1회 기준).
4. **보상형은 더 쓰고 싶은 사람:** 무료 한도 안내에 "광고 보고 채팅 5번 더". 하루 2~3회.
5. **무료 최대치 < 라이트(채팅 30번·통화 7분):** 예: 기본 10 + 광고로 최대 10~15번. 통화·포인트는 광고로 주지 않음(주더라도 보상형 2회 = 1분).
6. **구독자는 광고 없음:** 서버 요금 판정(`plans.ts`)이 유료면 광고를 띄우지 않음. 구독자가 한도를 다 쓰면 광고가 아니라 구매 포인트·상위 요금 안내.
   "광고 없이 쓰기"가 구독 이유로 더해짐.
7. **보상은 서버가 확인:** AdMob 서버 측 확인(SSV) 콜백을 새 API로 받아 KV에 그날 보너스를 더함. 앱이 "봤다"고 보내는 값만 믿으면 위조 가능.
8. **피로 관리:** 처음엔 횟수 적게, 다음 날 재방문율을 보면서 늘림.

**사람이 할 일**
1. AdMob 가입·앱 추가 — **했음(2026-10-18)**. 게시자 `pub-8959652589063151`, `app-ads.txt`는 서버 `public/`에(개발자 웹사이트 = english-chat-mvp.vercel.app). 인증 확인 대기.
2. 광고 단위 2개 — **만듦(2026-10-20)**: 전면 `ca-app-pub-8959652589063151/2248687484`, 보상형 `.../3513667692`. 앱 승인 "준비됨". 남은 것: 보상형 단위에 SSV URL `https://english-chat-mvp.vercel.app/api/ads/ssv`.

**개발이 할 일**
- 플러그인 `@capacitor-community/admob`(2026-10-18 기준 8.2.1, 앱은 Capacitor 8.3) — 네이티브라 PC에서 `npm install` + `cap sync`, 새 빌드.
- `AndroidManifest.xml`에 AdMob 앱 ID meta-data, AD_ID 권한. 개발 중엔 Google 테스트 광고 단위만(실제 광고를 자기가 누르면 계정 정지 위험).
- 서버(바로 반영): 광고 설정 API(비율·간격·상한, 유료면 꺼짐), SSV 콜백 route(서명 확인 → KV 보너스), 채팅 한도에 그날 보너스 더하기. 모델을 안 써서 `meterRequest` 불필요.
- 앱(빌드 필요): 자연스러운 끝에 전면 광고, 한도 안내에 "광고 보고 더" 버튼, UMP 동의, 문구 14개 언어.
- 처리방침 en/ko, `PRODUCT.md`(무료 한도), `plan-cost.mjs`에 광고 보너스까지 쓴 무료 최악 비용과 광고 수익.
- iOS 1차엔 넣지 않음(ATT 필요) — `platform.ts`에 한 줄.
- 먼저 2.67 실측(채팅 한 통 실제 원가)이 나오면 위 표를 다시 계산 — 지금 채팅 2원은 가정.

## 사용자가 정할 것

- 광고를 넣을지 최종(처리방침·"광고 ID 안 씀" 약속을 바꾸는 일).
