## 원칙

한 기능을 "만들기 → 살피기 → 고치기"로 나눈다. **만들기는 싼 모델(Haiku 5.5)**, 고가 모델(Sonnet·Opus)은 아래 넷 중 하나일 때만 끼운다.

1. **위험 신호가 있을 때만**(대부분 턴은 그냥 통과). 신호는 이미 있는 규칙 검사에서 나온다 — 비용 0.
2. **결과가 오래 남을 때**(지도·미션·약점 기록·표현 장부). 한 번 틀리면 몇 주 동안 학습자를 끌고 다닌다.
3. **결과를 여러 사람이 나눠 쓸 때**(영상 줄 자막 400일 공유 캐시, 노트 주제 캐시, 장면 목소리). 한 번 비싸게 만들면 모두가 쓴다 → 사람당 원가는 거의 0.
4. **기다려도 되는 자리**(통화 끝난 뒤 돌아보기, 응답 뒤 `after()`로 도는 기록 단계). 실시간 답(채팅 답·통화 턴)은 빨라야 해서 기본은 싼 모델.

고가 모델은 "다시 처음부터"가 아니라 **좁은 일 하나**만 맡긴다(예: "이 고친 문장이 맞나, 틀렸으면 고쳐라"). 입력이 짧아 비용·지연이 작다.

## 비용 어림 (2,000/300 토큰, 1,400원/$)

- 지금 채팅 한 턴: gpt-4o-mini 약 0.67원(2027-01-14 종료).
- Haiku만: 약 0.49원.
- Haiku + 위험한 턴만 Sonnet 확인(확인 호출 800/150 토큰 ≈ 4.3원, 15% 턴): **약 1.1원**.
- Haiku + Opus 확인 15%: 약 1.8원.
- 전부 Sonnet: 약 9.8원.
- 유료 요금이 이미 손해 구조(`hub/costs.md`)라 확인 비율이 핵심 — 비율을 Vercel 값으로 조정하고 하루 확인 횟수 상한을 둔다. 요금제별로 다르게(무료 위험 턴만, 프리미엄은 고친 턴 전부) 할 수 있다.

## 만들 때 (2단계 키를 받은 뒤)

1. `llm.ts` 표에 확인용 기능 추가(`chatVerify`·`explainRepair`·`missionRecheck`·`ledgerConfirm`, 등급 high) + op를 `modelCalls.ts`·`opCost.ts`에(CI `cost`).
2. 신호는 서버 한 곳(`correctionRisk.ts` 같은 것)에서 계산해 로그에 남김 — 실제 비율을 운영에서 보고 정함.
3. 켜고 끄기: `VERIFY_CHAT=off|risky|all`, `VERIFY_DAILY_MAX`. 기본 off로 배포 → 미리보기에서 켜고 비교.
4. 비교: 같은 `sim:users --suite tiers` 두 씨앗 + Claude 평가로 "Haiku만" vs "Haiku+확인" vs "지금". 지연(p95)도 같이.
5. 앱 빌드 필요 없음(서버만). 단, "답은 먼저 보여 주고 확인 결과로 나중에 바꾸기"를 하려면 앱 빌드가 필요 — 1차는 위험한 턴만 기다렸다 보내는 쪽.

## 정할 것

- 확인 모델: Sonnet(4.3원) vs Opus(8.7원) — 교정 비교에서 둘 다 거의 완벽, Sonnet으로 시작 제안.
- 요금제별 확인 범위(무료도 위험 턴은 확인할지).
- 지연 허용: 위험한 턴에 1~2초 더 걸려도 되는지.
