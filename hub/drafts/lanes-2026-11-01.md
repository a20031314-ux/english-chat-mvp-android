# 작업 줄(lane) — 탭별로 나눈 채팅 + 개발↔점검 순환 (설계 초안, 2026-11-01)

> 사용자 질문: "여러 채팅에 작업을 나눠 하는 게 문제 — main에 채팅별 리팩토링 로직을 넣어 해결할 수 없나",
> "코드변경 > 가상사용자 점검 > 피드백 > 다시변경을 1>2>2>1로 두 채팅에서", "My·AI 상호작용·사용자 간 상호작용 탭이 독립이면 여러 채팅도 괜찮아 보인다".

- **개발↔점검 순환 도구도 이미 있다:** `scripts/ux-check/`(driver → 인물 `/mark` → `triage.mjs` → `FIX.md`). 지금은 한 채팅이 점검하고 이어서 고친다(11-01 표시 103개).
- **일이 My에 몰려 있다**(지난 1주 커밋이 건드린 경로): `src/lib/curriculum` 460 · `components/studyMap` 133 ↔ `lib/roleplay` 51 · `lib/rooms` 49 · `components/rooms` 22. 탭별로 나누면 My 줄이 가장 바쁘고 나머지는 한가하다.

  - `hub/inbox.md`, `hub/roles/dev.md`(292줄 — 규칙의 "두 화면"을 넘음, 모든 탭의 열린 일이 한 파일)

  - `src/lib/copy.ts`·`src/lib/locales/overlays.json`(모든 새 문구), `src/lib/server/llm.ts`·`modelCalls.ts`·`billing/opCost.ts`·`aiDefaults.ts`

## 2. 작업 줄 셋 + 공통

줄의 범위는 `scripts/structure.json`의 영역을 묶어서 정한다(영역 → 줄). lib·server 파일은 줄마다 경로 목록으로 더한다(`hub/lanes.json`).

| 줄 | 화면 영역 | 주로 만지는 lib·server |
|---|---|---|
| **my** — My 탭 | `my` | `lib/curriculum/` · `lib/notes/` · `studyMapClient.ts` · server `stageScriptStore`·`scriptProgressStore`·`qbank`·`wordCards`·`wordExtras`·`frameLesson`·`recallPrompts`·`curriculum*`·`notebookStore`·`growthStore`·`selfCheckStore`·`weakPointStore`·`itemStatsStore`·`stage*` |
| **ai** — AI 상호작용 | `chat` · `call` · `video` | `lib/roleplay/` · `lib/pack/` · `callLines`·`callSession`·`realtimeCallSession`·`chatStream`·`chatPartner`·`correction*`·`tutorLanguage`·`conversationMode/Voice` · `lib/videoSubtitle/`·`contentDiscovery/`·`video*` · server `turn`·`realtimeSpeech`·`secondListen`·`packStore`·`sttProviders`·`video*` |
| **people** — 사용자 간 상호작용 | `talk` · `people` · `room` · `random` · `invite` | `lib/rooms/` · `lib/random/` · `lib/invite/` · server `dm`·`group`·`room*`·`board`·`social`·`presence`·`icon*`·`media`·`random`·`identity*`·`suspension`·`team`·`invite*` |
| **공통** — 메인 채팅이 맡음 | `shell` · `sheet` · `learner` · `account` · `billing` · `feedback` · `web` · `ops` | `conversation/` · `appIntents.ts` · `AppHome` · `features.ts` · `platform.ts` · server `llm`·`aiDefaults`·`modelCalls`·`opCost`·`kv`·`meterRequest` · `package.json` · `PRODUCT.md`·`STATE`·`RULES`·`STRUCTURE` 위쪽 |

- 사용자가 말한 "AI 보이스룸"은 지금 앱에 없다(AI는 채팅·통화, 보이스룸은 Room = 사람끼리). AI 튜터 카드(`AiTutorProfile`)는 사람 탭 화면이지만 ai 줄 기능이라 ai 줄이 고치고, 사람 탭 목록에 붙는 자리만 people 줄.
- 영상 학습 탭은 사용자가 말한 셋에 없어 ai 줄에 넣었다(정할 것 1).
- **"추가만" 예외:** 줄 채팅도 공통 파일에 *새 줄을 더하는 것*은 한다 — `copy.ts` 새 키·`overlays.json` 새 키, `structure.json`·`data-map.json` 자리, `modelCalls`·`opCost`의 새 op. 기존 줄을 고치거나 지우는 것은 메인 채팅에(받은 일 `hub/inbox/main.md`).

## 3. 채팅 구성

| 채팅 | 하는 일 |
|---|---|
| **메인(통합)** 1 | 공통 영역 소유, 줄이 넘긴 공통 수정, **정리(리팩토링)** — 줄끼리 같은 걸 따로 만든 것, 같은 기능 다른 이름(RULES "같은 기능 = 같은 이름"), 줄 경계를 넘은 커밋, STRUCTURE 위쪽 정리. 버전 자르기 전 통합 확인. 처음 질문의 "main의 리팩토링 로직" = 이 채팅 + 아래 6절 자동 검사 |
| **줄 개발** 3 | my · ai · people. 자기 줄 파일만 고친다 |
| **점검** 1 | 모든 줄 공통(qa). 가상 사용자 점검은 빌드 1번에 인물 셋이 앱 전체를 쓰는 무거운 일이라 줄마다 두지 않는다. 결과를 줄별로 나눠 넘긴다 |
| store | 출시 때만(지금 그대로) |

## 4. 순환 1 > 2 > 2 > 1

```
줄 개발(1) ── 고치고 push ──▶ hub/lanes/<줄>.md  "차례: 점검 · 볼 것: 화면·언어 조합·중립 과제"
                                        │
점검(2) ◀── 차례가 '점검'인 줄을 모아 한 번에(build:capacitor 1번, 인물 셋)
   └ /mark·체감 점수 → triage를 줄별로 → hub/lanes/<줄>.md "라운드 n 결과" + "차례: 개발"
                                        │
줄 개발(1) ◀── 받은 결과 고침 → 다시 "차례: 점검"
```

- 라운드마다 `hub/lanes/<줄>.md` 맨 위 칸(차례·라운드·마지막 점검 커밋)만 바뀐다. 결과는 `hub/drafts/ux-marks-<날>-<줄>.md`.
- **끝:** 새 표시 0, 또는 라운드 3번 → 사용자에게 점수 비교와 남은 것 보고.
- **사용자가 할 일:** 탭을 옮겨 "차례 왔어" 한마디(채팅끼리 서로 깨우지 못함). 허브 페이지에 줄마다 차례를 크게 보여 어느 탭으로 갈지 한눈에.
- **지금 규칙과 달라지는 점:** RULES "난이도 표시는 그 채팅에서 바로 고친다"(11-01) → 점검 채팅이 찾고 **줄 채팅이 고친다**. 그 밖 체감 문제는 지금처럼 보고만, 순서는 사용자(정할 것 3).
- 줄이 한가할 때(people·ai)는 줄 채팅 혼자 점검 에이전트를 띄워 1채팅으로 돌려도 된다 — 그 줄 화면만 짧게.

## 5. 충돌을 없애는 파일 나누기

| 지금 | 바꾼 뒤 |
|---|---|
| `hub/roles/dev.md` 하나 | `hub/lanes/{my,ai,people,main}.md`(차례 칸 + 열린 일 + 받은 결과), `roles/dev.md`는 개발 공통 규칙만 |
| `hub/inbox.md` 하나 | `hub/inbox/<받는 쪽>.md`(my·ai·people·main·qa·store) — 보내는 쪽은 받는 파일 끝에 한 줄 |
| `hub/log/2026-11.md` 하나 | `hub/log/2026-11/<줄>.md` — 줄마다 덧붙여 동시에 끝내도 안 부딪힘. 끝내기 훅은 `hub/log/`로 시작하는 파일이면 기록으로 세므로 검사는 그대로 동작 |
| STRUCTURE 위쪽 My 한 줄 | 탭마다 칸으로 나누고, 줄은 자기 칸만 |

## 6. 메인에 두는 자동 검사 (사용자가 처음 물은 "로직")

- **줄 정하기:** `/hub-my` · `/hub-ai` · `/hub-people` · `/hub-main`으로 시작하면 세션 상태에 줄을 적는다(시작 훅이 그 줄 파일·받은 일만 넣음).
- **줄 경계 검사(`scripts/lane-check.mjs`, 끝내기 훅):** 이번 채팅 커밋의 파일을 `hub/lanes.json`(줄 → 영역 + 경로)과 대조. 남의 줄 파일을 고쳤거나 공통 파일을 "추가만"이 아니게 고쳤으면 끝내지 못하고 → 되돌리거나, 그 줄/메인 받은 일에 넘기거나, 로그에 `- 줄 밖: 파일 · 이유` 한 줄.
- **CI(main):** 같은 검사를 push마다 돌려 줄 밖 수정을 `hub/inbox/main.md`에 모은다 → 메인 채팅의 정리 목록.
- **정리 주기:** 메인 채팅이 하루 한 번(또는 버전 자르기 전) 그 목록 + "이름 맞추기"를 처리. 원하면 예약 작업으로.

## 7. 브랜치는 쓰지 않는다

지금처럼 줄 채팅도 main에 바로 push(작은 커밋, push 전 `git pull --rebase`). 이유: Vercel이 main을 배포하고, 하루 커밋이 수십 개라 통합 채팅이 매번 머지하면 그 채팅이 병목이 된다. 충돌은 줄 경계와 파일 나누기로 막는다.
예외: 공통 영역의 큰 리팩토링은 메인 채팅이 브랜치에서 하고, 줄 채팅들이 쉬는 때 합친다(허브 페이지에 "공통 작업 중" 표시).

## 8. 넘어가는 순서 (고르면 이대로)

1. `hub/lanes.json` + `hub/lanes/{my,ai,people,main}.md` — `roles/dev.md` 열린 일을 줄별로 옮김.
2. `hub/inbox/` 나누기 + 시작 훅이 줄의 받은 일만 넣게.
3. 로그를 `hub/log/2026-11/<줄>.md`로, 허브 페이지(`hub-page.mjs`)가 폴더도 읽게.
4. `/hub-my`·`/hub-ai`·`/hub-people`·`/hub-main` 스킬, `lane-check.mjs` + 끝내기 훅 + CI.
5. 허브 페이지에 줄별 차례 칸.
6. RULES·hub/README·AGENTS(영어 Hub 절) 반영, ux-check `triage.mjs`가 표시를 줄별로 나눔.

## 9. 정할 것 (사용자)

1. 영상 학습 탭을 ai 줄에 넣을지 (제안: 넣음).
2. 점검 채팅을 하나로 모든 줄을 볼지 (제안: 하나) / 줄마다 둘지.
3. 난이도 표시 바로 고치기를 "줄 채팅이 고침"으로 바꿔도 되는지 (제안: 바꿈).
4. My 줄이 너무 바쁘면 My 안을 Stagebank·Quizbank·Logbank로 또 나눌지 — `lib/curriculum`을 셋이 같이 써서 **비추천**, 대신 My 줄 하나 + 다른 줄 채팅을 먼저 닫는 순서로.
