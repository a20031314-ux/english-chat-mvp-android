# 가상 사용자 세분화 점검 흐름 (사용자 결정 2026-10-19 밤)

문장 종류를 1차로 나눠 칸마다 "보통 결과"를 기준으로 남기고, 기준에서 벗어난 칸만 2·3·4차로 더 쪼개 계속 돌린다.
명백한 문제는 고치고(고친 뒤 모든 칸 기준을 다시 돌려 다른 데가 나빠지지 않았는지 확인), 판단이 필요한 것은 보고한다.

## 단계

| 단계 | 내용 | 상태 |
|---|---|---|
| 1 | 1차 8칸 정의·기준 실행·보고 (`--suite tiers`, `tiers.json`, `tiers-report.mjs`, 기준 `scripts/sim-users/baselines/tiers.json`) | 끝(2026-10-20) |
| 2 | 답 평가·문장 만들기: 서버가 가진 모델 키로 대신 부르는 점검 전용 주소(비밀 키 해시만 저장소에, 하루 상한, 비용 표에 `simJudge`) | 끝(2026-10-20) — 서버 주소 대신 **Claude가 평가**(가장 정교, 키·서버 변경 없음). 첫 결과 `sim-judge-2026-10-20.md` |
| 3 | 기준에서 벗어난 칸만 자동으로 쪼개기(예: 실수 하나 → 말투 → 선생님께 반말 → 짧은/긴/받아쓰기형) | 2 뒤 |
| 4 | 예약 실행(매시간 가볍게·매일 밤 전체, 기준과 달라진 칸만 `hub/reports.md`) | 3 뒤 |

## 1차 8칸

맞는 문장 · 약간 틀림(실수 하나: 조사·시제·일치·어순·철자·말투·단어) · 많이 틀림 · 편한 말 낱말 섞음 · 편한 말로만 · 소극적 대화 · 엉뚱한 입력 · 단체방 겹침.

## 고치는 것 / 보고하는 것

- 바로 고침(서버): 오류·빈 답·잘못된 언어·권한 뚫림·데이터 꼬임처럼 명백한 것. 예: 2026-10-20 동시 보내기 순서·동시 초대 받기 버그.
- 보고(사용자가 정함): 모델 판단(말투를 짚을지, 맞는 문장을 다듬을지), 한도·요금·기능 방향, 앱 빌드가 필요한 것.

## 2단계 대안 (서버에 주소를 더하지 않는 길)

- GitHub 비밀값에 OpenAI 키(점검 전용으로 새로 만든 키, 사용 한도를 낮게)를 넣고 Actions에서 평가 — 서버는 그대로.
- 사용자 PC에서 `OPENAI_API_KEY`를 두고 `--judge`(이미 있음, `scripts/sim-users/llm.mjs`).

## 고도화 제안 (2026-10-20, 사용자 승인 대기)

분석·설계 문서: https://claude.ai/code/artifact/979df099-4cd5-448d-a410-f0b5855d6788 — 회귀·탐색·오류 집중·장기 학습자 네 갈래가 하나의 오류 장부(지문)를 공유.
