## 남은 것

1. 사용자가 목소리 샘플(영어·한국어·일본어, 지금/새 방식) 듣고 OK → `TTS_ENGINE=realtime`·`OPENAI_TURN_TRANSCRIBE_MODEL=gpt-transcribe` 기본값 전환 + `billing/cost.ts` 단가(`TTS_USD_PER_MINUTE`, `CALL_TRANSCRIBE_USD_PER_MINUTE`) 같이 고침.
2. 통화 안 받아쓰기(`realtimeCallSession.ts` `OPENAI_REALTIME_TRANSCRIBE_MODEL`): Realtime 세션 안이라 `gpt-live-transcribe`(분당 $0.017)인지 `gpt-transcribe`가 되는지 실제 통화로 확인.
3. **영상 받아쓰기(whisper-1)는 그대로 못 바꿈:** 자막 시간 맞추기에 낱말·구간 시간(`timestamp_granularities`)을 쓰는데 whisper-1에만 있음. 짧은 조각으로 잘라 조각 시간으로 맞추는 방식 등 따로 설계 필요(2027-02-26 전).
4. 녹음해 둔 장면 대사(`scripts/build-roleplay-audio.mjs`, gpt-4o-mini-tts)는 파일이라 계속 재생되지만, 새로 만드는 줄은 다른 모델 목소리 → 장면 안에서 느낌이 다를 수 있음. 01-06 전에 새 방식으로 다시 녹음할지.

## Scribe v2 · AssemblyAI + 고가 모델 개입 설계안 (2026-10-21, 사용자 요청 — 아직 안 만듦)

- 확인한 것(문서): Scribe v2 — 90+ 언어(14개 모두), 낱말 시간, keyterm(일괄 1,000개·실시간 50개), 실시간 약 150ms, `no_verbatim`(끄면 말 그대로). 낱말 확신도는 문서에 없음.
  AssemblyAI — 낱말 시간, 스트리밍 p50 약 150ms, 일괄 99개 언어(Universal-2), 지시문(prompt)·code-switching은 Universal-3 Pro(지시문 쓰는 언어가 일부 — 문서마다 다름), keyterm 1,000개. 학습자 문법 실수를 그대로 두는지는 두 곳 다 문서에 없음 → 시험.
- 원칙: 고가 모델은 **빠른 길 밖**에서만. 빠른 자막은 받아쓰기 모델이 바로, 고가 모델은 뒤에서 고쳐 그 자리에서 바꿈. 고가 모델은 **잘못 들은 것만** 고치고 학습자 문법은 안 고침. 시간은 모델이 지어내지 않고 낱말 시간에서만.
- 정확도: 두 받아쓰기(Scribe·AssemblyAI)가 **다르게 들은 곳만** 고가 모델이 앞뒤 대화·방 주제·영상 내용을 보고 고름(둘 다 실제 소리를 적은 것이라 문법을 고칠 틈이 적음). 같으면 그대로.
- 자막 타이밍(영상): 낱말 시간 → 고가 모델이 뜻 단위로 줄을 나눔(낱말 번호 범위로 답, 시간은 낱말에서) → 줄 시작·끝이 소리에 정확히 붙음. 이달의 영상은 한 번 만들어 모두가 쓰니 Opus도 감당, 사용자가 넣은 링크는 Haiku.
- 반응 속도(Room·통화): 고가 모델로는 빨라지지 않음 — 스트리밍 받아쓰기(말하는 중에 글자가 뜸, 지금은 쉼 뒤 1~2초)가 답. 앱이 소리를 서버 거쳐 웹소켓으로 보내야 해서 **앱 빌드 필요**. 스트리밍은 마이크가 켜진 동안 과금(AssemblyAI는 세션 분) — 말할 때만 열기.
