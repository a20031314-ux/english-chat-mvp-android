# 모를 것·헷갈릴 것·필요할 것을 추정해서 계속 던져 주기 (설계안, 2026-10-29)

> 사용자 2026-10-29: "단어나 퀴즈도 그냥 주는 게 아니라 사용자가 모를 것이다, 헷갈릴 것이다, 필요할 것이다 이런 걸 추정해서 계속 던져 주도록 할 수 있어?"
> 상태: **설계안 — 사용자 결정 전.** 앞 단계: 약한 곳 퀴즈(`today-weak-practice-2026-10-28.md`, 2.76), 지난번에 틀린 것·아침 알림·대화 속 다시 쓰기(2.77, `weakSpots.ts`·`morningDigest.ts`·`reuse.ts`).

## 지금은 "이미 틀린 것"만 다시 준다

오늘 할 것·지난번에 틀린 것·아침 알림·튜터 다시 쓰기의 재료는 모두 **이미 일어난 일**이다:
고친 줄, 대본 🎤 틀린 줄, 헷갈려요, 직접 물어본 곳. 틀리기 전에는 아무것도 오지 않고, 단어는 커리큘럼 순서대로 온다.

바꾸는 것: 표현·문장구조·단어 하나하나에 **"이 사람이 지금 이걸 모를 확률"**을 매기고, 그 확률이 적당한 것(너무 쉽지도 너무 어렵지도 않은 것)을 계속 던진다. 던진 결과(맞음·틀림)로 확률을 다시 고친다.

## 1. 추정 — 세 갈래, 모델 안 씀

열쇠는 지금과 같다(`e|표현` · `f|문장구조` · `g|단계:문법`). 각 열쇠에 아래 신호를 더해 점수 하나를 만든다.

### 모를 것 (아직 못 꺼내는 것)
| 신호 | 어디에 이미 있나 |
|---|---|
| 본 적만 있음 — 찾아봄·번역·분석만 하고 내가 쓴 적 없음 | 표현 장부 `met`, `learnerComprehension:v1`(lookup·translate·analyze) |
| 대본에서 원문을 열어 봄·첫 글자 힌트로만 맞힘 | 대본 결과(revealed·hint 방식) — 지금 버림 → 폰에 기록 |
| 편한 말로 쓰고 "표현 보기"를 눌렀는데 답이 배운 표현·문장구조 ("배웠는데 못 꺼냄") | 표현 보기 답 — 대본 커리큘럼 설계 5절 "피했다" 신호 |

### 헷갈릴 것 (아직 안 틀렸지만 틀릴 것)
| 신호 | 어디에 이미 있나 |
|---|---|
| **같은 종류 실수** — 튜터가 고친 실수 종류(예: 과거 시제, 조사 を)를 아직 연습 안 한 다른 문장구조·대본 줄이 쓰면, 그것도 위험 | 실수 종류 `weakPointStore`(종류 열쇠만) + 문장구조·대본의 문법 태그 |
| **같은 모국어 학습자들이 많이 틀린 것** — ko→ja, ar→es처럼 언어 조합별로 문장구조·대본 줄마다 틀린 비율 | 새 집계(숫자만, 아래 4절) |
| 비슷한 꼴끼리 — 같은 단계의 닮은 조각(~てもいい / ~てはいけない, ser / estar) 중 하나만 익힘 | 문장구조 `fn`(공통 기능)·`core` 조각 |

### 잊을 것 (알았는데 흐려질 것)
| 신호 | 어디에 이미 있나 |
|---|---|
| 익혔거나 통과했는데 그 뒤로 오래 안 씀 — 칸마다 쓴 횟수에 따라 1·3·7·14·30일 간격 | 장부 `lastAt`·outputs, 대본 통과 때 |

### 필요할 것 (곧 쓸 것)
| 신호 | 어디에 이미 있나 |
|---|---|
| 오늘·내일 할 대본에 나오는데 아직 처음 보는 표현·낱말 → **대본 전에 미리** | 오늘 할 것 목록 + 장부 |
| 내 관심사·하는 일(프로필 칩)과 최근 대화 주제에 자주 나오는 표현 | `profileFacts`, 노트 칸 |
| 다음 단계로 넘어가는 데 모자란 갈래(어휘·문법·표현·발음) | `stageParts` |

### 점수 하나로
`모를 확률 = 문제 난이도(집계·단계) − 내 실력(그 갈래 맞힌 비율) + 신호 가산 + 잊음(마지막으로 맞힌 뒤 지난 날)`
— 문제를 낼 때마다 결과로 내 실력과 그 열쇠의 값을 고친다(간단한 Elo 방식, 폰과 서버 어디서 계산해도 같은 결과).

**던질 것 고르기:** 확률이 약 40~75%인 것("조금 어려운 것")을 먼저. 90% 넘게 모를 것은 퀴즈 대신 그 대본(먼저 배우게), 20% 아래는 안 던짐.

## 2. 계속 던지기 — 자리

| 자리 | 지금 | 바뀌면 |
|---|---|---|
| 오늘 할 것 | 약한 곳 퀴즈(이미 틀린 것) + 새 대본 | 약한 곳 + **예상 퀴즈**(모를·헷갈릴·잊을 것) + 대본 앞 **미리 볼 낱말 3개**(필요할 것) |
| 퀴즈 끝 | 끝 화면 | **"한 문제 더"** — 다음 예상 문제를 바로. 연속 2개 틀리거나 사용자가 그만할 때까지 (끝없이) |
| 아침 알림 | 틀린 것 하나 + 단어 n개 | 그날 확률 가장 높은 것 하나(이유 꼬리표 포함) + 필요할 단어 |
| AI 대화·통화 | 헷갈려요 표현 둘을 튜터가 다시 쓰게 | 예상 목록 위쪽 둘도 같이 — 튜터가 그 표현이 나올 질문을 함 |
| 대본 시작 | 바로 시작 | 처음 보는 표현이 있으면 맨 위에 그 표현 칩(누르면 뜻·듣기) |

퀴즈 칸에 **짧은 꼬리표**만 붙인다: `처음 봄` · `헷갈리기 쉬움` · `잊을 때` · `곧 나옴`. 설명 글은 사용법(?) 칸에만(RULES 4).

## 3. 맞았는지로 고친다 — 추정이 맞는지도 잰다

- 예상 퀴즈를 맞히면 그 열쇠 확률을 내리고 7일 뒤 한 번(사다리는 지금 퀴즈와 같음), 틀리면 지금 다시 볼 것으로.
- **보정 기록:** 꼬리표마다 "예상대로 틀린 비율"을 센다(숫자만). 예를 들어 "헷갈리기 쉬움"이 실제로 10%만 틀리면 그 신호 가중을 낮춘다. 주 1회 `hub/reports.md`에 꼬리표별 적중률 한 줄(가상 사용자 일일 보고에 붙임).

## 4. 저장 (문장은 저장하지 않음)

| 무엇 | 어디 | 누구 것 |
|---|---|---|
| 열쇠별 내 값(맞음·틀림·마지막 때·꼬리표) | 서버 `stageScripts:v1`에 칸 추가(지금 review 옆, 400개) — 폰 바꿔도 이어짐 | 나, 계정 지우면 함께 |
| 대본 힌트·원문 열기 | 폰(`scriptMisses.v1` 옆) | 나 |
| 언어 조합별 열쇠·대본 줄 틀린 비율 | 새 공유 키 `predict:v1:<모국어>:<학습 언어>` — 열쇠 → {낸 수, 틀린 수}만 | 공유, 점검 사용자 `simcheck-` 제외 |

새 공유 키는 `scripts/data-map.json`에 한 줄. 처리방침에 "어떤 문제를 틀렸는지 숫자로 모아 다른 학습자에게 어려운 문제를 고르는 데 씀"을 한 줄 넣는다.

## 4-1. 얼마나 공부했나·얼마나 늘었나 (사용자 2026-10-29 "공부한 단어 n개, 얼마나 향상 중인지도")

지금 있는 것: My "대본으로 익힌 것"(통과한 대본·문장구조 기준 표현·문법·문장구조 수, 말한 문장 수), 네 갈래 망·그래프(갈래별 14일), 프로필 공부 기록 칸(켰을 때). **없는 것:** 단어·표현을 몇 개 공부했는지(퀴즈·대본·대화를 합쳐서), 그리고 실제로 나아지고 있는지.

추정 점수(1절)가 있으면 둘 다 같은 기록에서 나온다 — 열쇠마다 "모를 확률"이 시간에 따라 어떻게 내려갔는지.

| 보일 숫자 | 정의 |
|---|---|
| **공부한 단어·표현 n개** | 한 번이라도 퀴즈·대본·대화에서 다뤄 기록이 생긴 열쇠 수(오늘 +n, 이번 주 +n) |
| **익힌 것 n개** | 모를 확률 20% 아래로 내려간 열쇠 — 그중 혼자 대화에서 쓴 것은 ✓ |
| **굳힌 것 n개** | 예상(헷갈릴·잊을 것)으로 던졌는데 맞힌 것, 7일 뒤에도 맞힌 것 — "약했다가 나아진 것" |
| **향상** | 같은 단계 열쇠 전체의 평균 모를 확률 — 2주 전 대비 몇 % 내려갔나, 날마다 한 점(그래프) |
| **처음 풀 때 맞힌 비율** | 예상 퀴즈 첫 답 정답률, 주별. 추정이 잘 맞으면 50~65% 근처에 머무는 게 정상이라 이건 보조 숫자 |

화면: My 단계 보기 맨 위 "대본으로 익힌 것" 카드를 넓혀 [공부한 단어 · 익힌 것 · 굳힌 것] 숫자 셋 + 오늘·이번 주 +n, 아래 향상 선 하나(14일·8주 고르기 — 보는 방식 고르기 규칙). 숫자를 누르면 그 목록(무엇을 언제 익혔나, 누르면 그 대본·퀴즈). 지금의 네 갈래 그래프에 "모를 확률" 선을 겹칠지는 따로.
아침 알림 머리 한 줄에도 "어제 +n 익힘"을 넣을 수 있다. 프로필 공부 기록 칸(켰을 때)에 "익힌 단어 n"을 더할지는 사용자.

저장: 열쇠별 값(4절)에 처음 다룬 때·익힌 때·굳힌 때만 더한다. 향상 선은 날마다 평균 하나(언어별 90일, 숫자만).

## 5. 만드는 순서

1. **내 신호로만** (앱 빌드, 서버 조금) — 모를 것(본 적만·힌트) + 잊을 것 + 같은 종류 실수 + 필요할 것(대본 앞 칩). 점수·고르기는 `lib/curriculum/predict.ts`(순수, 테스트). 오늘 할 것에 예상 퀴즈 칸 + 퀴즈 끝 "한 문제 더" + **진척 카드(공부한 단어·익힌 것·굳힌 것, 향상 선)**.
2. **집계** (서버) — 언어 조합별 틀린 비율 쌓기 시작. 처음엔 숫자가 적어 가중 0 → 문제마다 30명 넘으면 켬.
3. **대화·알림에도** — 튜터 다시 쓰기·아침 알림이 예상 목록을 같이 씀. 보정 기록 보고.

비용: 모델 호출 0(퀴즈·점수 모두 폰·서버 계산). "배웠는데 못 꺼냄" 판정만 표현 보기 답에 이미 있는 글을 낱말 맞춤.

## 정할 것 (사용자)

1. 하루 분량 안에서 몫: 이미 틀린 것 / 예상 / 새 대본 — 제안 3 : 3 : 4.
2. 퀴즈 끝 **"한 문제 더"(끝없이)**를 넣을지 — 제안: 예, 연속 2개 틀리면 멈추고 그 대본을 권함.
3. 퀴즈 칸 **꼬리표**(처음 봄·헷갈리기 쉬움·잊을 때·곧 나옴)를 화면에 보일지 — 화면 설명 금지 규칙과 부딪힐 수 있어 확인. 제안: 두세 글자 꼬리표만.
4. **다른 학습자 집계**(언어 조합별 틀린 비율, 숫자만)를 쓸지 — 처리방침 한 줄 필요. 제안: 예, 2단계에서.
5. 대본 앞 **미리 볼 낱말**을 자동으로 띄울지, 칩만 둘지 — 제안: 칩만(누르면 뜻·듣기).
6. 진척 숫자를 **프로필 공부 기록 칸**(남에게 보이는 곳)에도 넣을지 — 제안: "익힌 단어 n"만, 칸이 켜졌을 때.
