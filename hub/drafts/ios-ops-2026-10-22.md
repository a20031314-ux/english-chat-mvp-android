# iOS 출시 뒤 운영전략 (2026-10-22, 초안)

> 사용자 요청: "ios 출시 후 운영전략을 구상해줘". 상태: **초안 — 아래 "정할 것" 사용자 결정 대기.**
> 기준: main `bc8933b`, iOS TestFlight 2.70(84.7), 출시 준비는 `hub/drafts/ios-launch.md`, 손익은 `hub/economics.md`.

## 0. 출발점 — iOS 1차가 안드로이드와 다른 점

| | 안드로이드 | iOS 1차 | 운영에 주는 뜻 |
|---|---|---|---|
| 기능 | 대화·영상·사람·Room·My | 채팅·통화·영상(라이브러리만)·My | iOS는 **혼자 공부하는 앱**으로 평가받는다 |
| 로그인 | Google·아이디·이메일 | 아이디·이메일만 | 가입 단계 이탈이 더 클 것 |
| 광고 | 무료 사용자에게 | **없음** | iOS 무료 사용자는 1인당 평균 원가 약 390원/월이 그대로 손해(한도 꽉이면 2,418원) |
| 결제 | Play 15% | Apple(소규모 사업자 15%) | 같은 상품 id·다른 스토어 구독자는 구매 막음 |
| 출시 | 사람이 PC에서 빌드, 바로 | GitHub Actions → TestFlight → **심사 1~2일** | 급한 수정은 서버로, 앱 수정은 묶어서 |

**결론:** iOS는 처음 몇 달 "**유료 전환 채널 + 심사 통과 유지**"로 운영한다. 기능을 넓히는 건 안드로이드에서 먼저 검증된 것만, 2차에서.

## 1. 단계별 계획

### 1단계 — 출시 ~ 2주: 안정화
- **단계적 출시(Phased Release, 7일)** 켜고 제출 — 문제 생기면 멈춤.
- 매일 볼 것: App Store Connect 크래시·TestFlight 의견, 별점·리뷰(전부 답장, 48시간 안), 의견함(`/ops`), 결제 실패(RevenueCat).
- **AI 동의 시트 이탈률**이 iOS만의 첫 관문 — 동의 안 하고 닫는 비율이 높으면 문구부터 손본다.
- 새 기능 안 넣음. 고칠 것은 ① 서버로 고칠 수 있으면 바로(Vercel) ② 앱 수정이 필요하면 모아서 한 번, 막히는 버그면 긴급 심사 요청.

### 2단계 — 2~6주: 전환·유지
- **리뷰 요청**(시스템 별점 창, 1년 3번 제한): 지도 한 단계 끝낸 직후·통화 3번째 끝난 뒤처럼 성공한 순간에만. 지금 코드에 없음(dev).
- **구독 첫 혜택**(7일 무료 또는 첫 달 할인) 검토 — App Store 쪽은 상품 설정만으로 가능, 안드로이드와 같이 맞출지 결정.
- **8,900원 전환일**(`PREMIUM_DAILY_PLAN_FROM`)은 Play·App Store 가격 변경을 같은 날로. Apple은 기존 구독자 인상에 동의 절차가 있으니 날짜를 앞당겨 공지.
- App Store 제품 페이지: 스크린샷은 iOS에 있는 기능만(사람·Room 장면 금지), 맞춤 제품 페이지로 한국·일본 먼저.
- 복습 알림(APNs 푸시)은 유지에 가장 효과가 크지만 개발이 필요 — 2차 사회 기능 알림과 같이 설계.

### 3단계 — 6~12주: 2차(사람 기능) 준비
순서 제안 — 심사 위험이 낮은 것부터:
1. **Apple 로그인 + Google 로그인**(Google을 넣으면 4.8 때문에 Apple 로그인도 필요). 기기 바꾼 사용자·안드로이드 사용자가 같은 계정으로 들어오는 길.
2. **아는 사이 1:1 메시지·통화**(친구 초대 링크로 연결) — 모르는 사람 연결이 아니라 심사 부담이 작다.
3. **Room·사람 목록** — 1.2 요건(약관 동의·거르기·신고 24시간 처리·차단) 갖춘 뒤. `/ops`가 그 처리 화면 근거.
- **절대 안 넣음:** 랜덤 연결(Spin·Pingo) — 1.2에 "랜덤·익명 채팅 위주 앱은 예고 없이 내림". iOS 앱 안에서 그 웹 창구로 링크·안내도 하지 않는다.
- 켜는 방법은 **새 빌드로만**(`NEXT_PUBLIC_IOS_SOCIAL=1`). 서버 스위치로 iOS에서 숨긴 기능을 켜면 2.3.1(숨은 기능) 위반.

## 2. 출시 리듬 — 한 코드, 두 열차

- 안드로이드는 지금처럼 자주, iOS는 **2주에 한 번** 안드로이드의 최신 버전을 그대로(버전 번호는 `build.gradle`을 따라감).
- 서버는 모든 앱에 바로 반영되니, **옛 iOS 빌드가 최소 한 달 남는다**고 보고 API를 바꾼다(옛 앱 확인 목록에 iOS 추가).
- 알려진 구멍(dev 확인 필요):
  - 업데이트 배너 기준 `RECOMMENDED_APP_VERSION`이 하나뿐 — 안드로이드 기준을 올리면 **아직 그 버전이 없는 iOS에 업데이트 배너**가 뜰 수 있다. 플랫폼별로 나누거나 iOS는 App Store 버전 조회로.
  - "새로워진 점"에 플랫폼 거르기가 안 보임 — iOS에 없는 기능(Room·사람)을 안내하면 안 된다.
  - 의견함이 `platform`을 android/web만 받음(`api/feedback`) — iOS 의견이 web으로 섞임.
  - 크래시 수집 도구 없음 — 1단계는 App Store Connect 크래시로, 필요하면 나중에.
- 연말: Apple 심사가 12월 하순 쉬는 해가 많다 → **12월 중순 전 제출**. 모델 종료(통화 돌아보기 12-11, 목소리 01-06, gpt-4o-mini 01-14)는 서버 쪽이라 대부분 빌드 불필요 — 통화 튜터 스트리밍이 앱 코드에 묶여 있으면 12월 초에 iOS 빌드 포함 여부 결정.

## 3. 돈 — iOS를 손해 안 보게

- iOS 무료 사용자는 광고 수입 0 → 무료 비율이 높으면 그대로 손해. **가장 큰 단가는 지도 그리기(Sonnet, 1장 약 122원)** — 무료 하루 3장 한도를 낮추는 안(이미 제안됨)이 iOS에 특히 중요.
- 손익표(`sim:economics`)에 **iOS 열**(광고 0, Apple 15%)을 더해 매달 같이 본다.
- iOS 광고는 1차에 **넣지 않음** 권장(추적 동의 창(ATT)·심사·평판 부담, "광고 없음"이 구독 이유이기도 함). 다시 볼 조건: iOS 무료 사용자 원가 합이 한 달 고정비를 넘을 때.
- 구독은 Apple이 환불·해지를 처리 → RevenueCat 알림으로 서버 권한이 바로 꺼지는지 첫 환불 때 확인.

## 4. 매주 볼 숫자 (플랫폼별로 나눠서)

| 영역 | 숫자 | 첫 목표(가정) |
|---|---|---|
| 획득 | 제품 페이지 → 설치 전환, 검색어 | 기준선 잡기 |
| 시작 | AI 동의 통과율, 첫 채팅까지 간 비율 | 동의 90%+, 첫 채팅 70%+ |
| 유지 | 1일·7일·30일 다시 옴 | 안드로이드와 비교 |
| 돈 | 결제 전환율, 해지율, 환불 | 3%(손익표 가정) |
| 비용 | iOS 무료 1인 한 달 원가 | 390원 이하 |
| 품질 | 크래시 없는 사용자, 별점 | 99.5%+, 4.5+ |

서버 사용 기록에 플랫폼 표시가 있어야 나눌 수 있다 — 없으면 dev가 먼저 넣는다.
