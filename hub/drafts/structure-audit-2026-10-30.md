## 2. 반복되는 이유

1. **규칙은 있는데 막는 장치가 없다.** RULES 4 "화면 속 기능 부연설명 금지"는 10-22에 생겼고 같은 종류의 정리가 10-22·22·23·23·29·29에 반복됐다(`hub/log`). 색·크기 토큰은 CI `check:design`이 막지만, 문구는 사람 눈에만 기댄다. `ux-issues.md` U10 상태가 "열림(새 화면마다 다시 생김)".
2. **요청을 글자 그대로, 보이는 요소로 만든다.** "통과 기준을 정할 수 있게" → 화면 토글, "어휘·문법으로 헷갈리는 오답" → 보기에 어휘·문법 꼬리표. 요청의 뜻(오답을 다양하게)은 꼬리표 없이도 이뤄진다.
3. **기능끼리 부딪히면 설계 대신 문구로 메운다.** 연습 방식 × 통과 기준 → "통과로 안 셈".
4. **바꾸는 속도가 정리 속도보다 빠르다.** log: 10-29 하루 65항목, 10-30 오후 1시까지 17항목. My는 같은 날 안에서 "지속 학습 → 복습 → 다시 지속 학습 + 복습"처럼 되돌린 것이 있다. 뺀 것보다 더한 것이 많아 쌓인다.

## 3. 앱 전체에서 개념이 섞인 곳

**My 한 탭에 쓰이는 문구 301개**(copy.ts ko 1,452개 중), `NotebookSection.tsx` 2,233줄 · `TodayPlan.tsx` 1,366줄.

### 3-1. "방식"이 다섯 벌
- 단계: 상황 · 표현 · 문장구조
- 대본: 따라 말하기 · 첫 글자만 · 가리기 · 내 말로 · 고르기 · 맞추기 (+ 통과 기준 말하기만 · 모든 방식)
- 퀴즈(지속 학습·복습): 랜덤 · 빈칸 · 순서 · 듣고 고르기 · 말하기 / 어휘: 단어 맞추기 · 뜻 고르기
- 오늘 할 것 ⚙ 조합: 랜덤 · 말하기 · 듣기 · 읽기
- 지속 학습 탭(대상): 랜덤 · 어휘 · 문법 · 표현 / 네 갈래: 어휘 · 문법 · 표현 · 발음

### 3-2. 같은 이름 · 다른 뜻 (dev.md "이름 맞추기"와 겹침)
- **맞추기** = 대본 순서 맞추기 ↔ 단어 맞추기(짝짓기)
- **고르기**(대본) = **빈칸**(퀴즈) — 같은 일, 다른 이름
- **말하기** = 퀴즈 모양 · 조합 묶음 · 통과 기준 — 셋 다 다른 뜻
- **표현** = 단계 방식 · 네 갈래 · 지속 학습 탭 · "내 표현" 장부
- **랜덤** = 탭(모자란 갈래부터) ↔ 방식(모양을 돌아가며) — 한 화면에 둘
- **어휘·문법** = 갈래 탭 ↔ 오답 꼬리표

### 3-3. 진척 숫자가 스무 가지
n분 · n일 완성 · n단계 통과 · 오늘 +n 앎 · 바로잡음 n · 다시 볼 것 n · 배우는 중 n · 목록 밖 +n · 다음 단계까지 n개 · 다음 단계까지: 상황 n개 · 통과까지 n줄 · 통과 n/m · m개 중 n개 맞음 · 이번 주 +n · 표현 n/total · 다시 말해보기 n번 …
"앎" 상태 이름도 여럿: 앎 · 이미 앎 · 확인 중 · 배우는 중 · 숙지 · 들으면 앎 · 만난 것 · 익힌 것 · 할 수 있어요/비슷해요/아직 어려워요 · 통과 · 완료 · 끝까지 했어요.

### 3-4. 앱 범위
하단 탭 다섯(대화·영상·사람·Room·My) + 창구 셋(Moyeo·Pingo·Spin) · 게시판 · 아이콘 만들기·판매 · 방 게임 · 팀 워크스페이스 · 영상통화. 학습 앱의 핵심(My 대본·퀴즈)과 소셜 기능이 같은 무게로 커지는 중. 컴포넌트 62개 + 하위 폴더, API 92개.

## 4. 제안 (결정 전)

1. **문구 막는 장치** — `scripts/check-copy.mjs`(가칭): 화면 문구 중 문장형(…요/…셈/…면/…보세요)·내부 분류명을 화면 코드에서 새로 쓰면 CI 실패, 허용 목록(상태·오류·한도)만 통과. `check:design`처럼 기준선 파일로 지금 것은 두고 늘어나는 것만 막기.
2. **이 화면 바로 정리** — 통과 기준 토글·"통과로 안 셈"·어휘/문법 꼬리표·줄마다 방식 라벨 빼기, 점과 숫자를 한 뜻으로(통과로 세는 줄만). 오답 뒤에는 꼬리표 대신 한 줄 이유(있을 때만).
3. **이름 한 벌로** — 3-2를 한 표로 놓고 사용자가 고른 이름으로 한 번에(14개 언어).
4. **진척 숫자 정리** — My에 남길 숫자 2~3개를 먼저 정하고 나머지는 내 진척 시트 안으로.
5. **바꾸기 전에 한 장** — My처럼 하루에 여러 번 바뀌는 곳은 고치기 전에 STRUCTURE에서 "무엇을 빼는지"를 같이 적고 시작(더하기만 하는 커밋 막기).
