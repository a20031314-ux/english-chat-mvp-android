## 0. 한 줄

학습 언어 은행(1~5단계 문장구조·문법 칸·표현·낱말)을 **얼마나 채웠는지**를 갈래마다 하나의 어림으로 들고 다닌다.
처음엔 체크 한 번으로 어림을 놓고(넓은 범위), 답이 쌓일수록 범위가 좁아지며 실제에 수렴한다. 수렴한 갈래부터 약점을 찾고, 그 결과로 다음 주 오늘 할 것·Quizbank 순서를 정한다.

```
처음 체크(초보·중급·고급) ──► 갈래별 어림 θ (범위 넓음)
                                   │  답마다 고침(퀴즈·수업·시험·통화 고침·꺼내 쓰기·알아요)
                                   ▼
                          범위가 좁아짐 = 수렴 ──► 약점(어림보다 못 하는 칸) ──► 학습 방향(주마다)
                                                                                 ├ 오늘 할 것 "내 기록에 맞춰"
                                                                                 ├ Quizbank 순서·정기 시험 재료
                                                                                 └ Logbank에 보임
```

## 1. "몇 %"는 무엇의 몇 %인가

- 분모 = 그 학습 언어의 은행 전체(`curriculum/contentScope.ts` total — 1~5단계 문장구조·문법 칸·표현, 낱말은 5단계 컷까지).
- 갈래마다 따로: **📐 문법(문장구조 + 문법 칸) · 🔤 어휘 · 💬 표현** — Logbank 기준 탭과 같은 셋. ⏱ 학습 시간은 채움이 아니라 들인 양이라 따로 둔다.
- 전체 % = 세 갈래의 가중 평균(제안: 문법 0.4 · 어휘 0.3 · 표현 0.3 — 단계 조건이 문장구조 중심이라).
- 채운 몫 = Σ(항목마다 아는 확률) / 항목 수. 직접 증거가 있는 항목은 증거로, 없는 항목은 어림으로.

## 2. 시작 — 체크 한 번

- 처음 설치, 배울 언어 고르기 바로 뒤 한 줄: **[초보 | 중급 | 고급]**(+ 글자가 다른 언어면 "글자부터" = 0단계). 설명 글 없이 버튼만(RULES 4).
- 고른 것 → 갈래마다 같은 시작 어림 + 넓은 범위(불확실성). 숫자는 결정 대기(아래 표는 제안):

| 체크 | 시작 어림(전체) | 시작 단계 | 범위 |
|---|---|---|---|
| 글자부터 | 0% | 0 | ±5%p |
| 초보 | 10% | 1 | ±15%p |
| 중급 | 40% | 2~3 | ±20%p |
| 고급 | 67% | 4 | ±25%p |

- 시작 단계는 "어림 % ≈ 그 단계까지 쌓인 은행 몫"인 단계 — 지금의 StagePicker(대화 예시 고르기)·처음 시험(`placement.ts`)을 대신하거나 뒤로 미룬다(결정 대기 4).
- 어휘는 이미 `vocabLevel.ts`가 단계 시작에서 경계를 잡는다 — 체크가 그 시작값을 준다(`startLevel`).

## 3. 수렴 — 답마다 고치기

`vocabLevel.ts`(어휘 탭, 2026-11-01)를 세 갈래로 넓힌다. 같은 식:

- 항목 난이도 d = 그 항목의 자리(단계 + 단계 안 순서, 낱말은 빈도 순위). 모든 사용자의 첫 답 맞힌 몫(`itemStats:v1` — 이미 서버에 모음)이 쌓이면 그걸로 d를 고친다.
- 아는 확률 P = 1 / (1 + e^((d − θ)/σ)), 맞힐 확률 = g + (1 − g)·P(고르기 g = ⅓, 쓰기·말하기 0).
- 답 하나 → θ += K·w·(맞음 − 맞힐 확률). K는 그 갈래 답 수가 늘수록 작아진다(처음엔 크게 움직이고 나중엔 덜).
- 증거마다 무게 w(제안):

| 증거 | 어디서 | w |
|---|---|---|
| 시험·처음 시험·단어 시험 첫 답 | checkups, exam | 1.0 |
| Quizbank 첫 답 | quizDays, circle | 1.0 |
| 수업 통과/미통과 | dayLog | 0.7 |
| 꺼내 쓰기(뜻 보고 만들기) | dayLog recall | 0.8 |
| 튜터가 고친 줄(그 소재 틀림) | logItems fixed | 0.5 |
| 알아요로 넘김·이 단계 스킵 | 자기 판단 | 0.3 (맞음) |
| 쉬워요·어려워요 | vocabLevel feel | 경계를 크게 옮김(지금처럼) |

- 잊음: 익힘(`known.ts`)의 1·3·7일 다시 묻기에서 맞힌 몫 = **기억 유지율**. 유지율이 낮으면 직접 증거 없이 오래된 익힘의 확률을 조금씩 내린다.
- **수렴 판정:** 그 갈래 범위가 ±5%p 안(제안: 첫 답 40개 안팎). 그 전에는 범위를 흐린 띠로, 숫자는 "약 n%"로(결정 대기 1).
- 검증: 가상 사용자로 "참 실력 X인데 체크를 Y로 고른 사람"이 몇 문제 만에 X ±5%p에 닿는지 — 시뮬레이션(`scripts/`)으로 먼저 돌리고 K·σ·w를 정한다(체크를 틀리게 고른 경우가 핵심).

## 4. 약점 — 수렴한 갈래부터

- 약점 = **어림으로는 알아야 할 텐데 못 하는 곳.** 항목마다 (예상 맞힐 확률 − 실제 맞힌 몫)이 크고 증거가 둘 이상인 것.
- 묶어서 본다: 문법 칸·문장구조 하나·표현 주제 하나 단위(낱말 하나씩은 Quizbank 다시 보기로 충분). 묶음 점수 = 차이 합 × 단계 무게(낮은 단계일수록 큼 — 뼈대 구멍).
- 갈래 사이: 한 갈래 θ가 다른 둘보다 한참 낮으면 그 갈래 자체가 약점.
- 대화 쪽 신호(`gaps.ts` — 고친 줄의 새 말·표현 보기·뜻 본 낱말)는 뼈대 밖 약점으로 따로 둔다(채움 %에는 안 넣음, PRODUCT 핵심 가치 9).

## 5. 학습 방향 — 주마다

- 주 경계(Logbank 주와 같은 날)에 한 번 정한다: **갈래 비중**(예: 문법 50 · 어휘 30 · 표현 20) + **약점 1~3개**.
- 반영되는 곳:
  - 오늘 할 것 "내 기록에 맞춰"(`dailyPlan.ts` — 지금은 서버 scriptPick 하나만 맨 앞): 비중대로 새 것을 고르고 약점 묶음을 다시 볼 것 자리(분량의 절반까지)에.
  - Quizbank `nextStudy` 순서·정기 시험(`exam.ts`) 재료: 약점 묶음 열쇠 먼저.
  - Logbank: 이번 주 방향과 지난주 대비 채움 변화.
- 학습자가 고른 방향(예: "이번 달은 표현")이 있으면 그게 앞서고 기록은 그 안에서 약점만 고른다(결정 대기 2).

## 6. 저장·원가

- θ·범위·답 수·증거 무게 합 = 열쇠와 숫자만(문장 없음) → **계정에 저장**해 폰을 바꿔도 이어지게(제안 — `stageScripts:v1` known과 같은 자리, `scripts/data-map.json` 한 줄). 수업 결과의 내 줄(dayLog)·통화 기록은 그대로 폰에만.
- 모델 호출 없음 — 원가 0, Logbank·오늘 할 것 모두 순수 함수.

## 9. 화면 — 육각형 → 게이지 → 빈 곳(사용자 2026-11-02, 그림: 언어능력 지도 레이더)

사용자 흐름: **육각형(꼭짓점 = 변수) → 꼭짓점을 누르면 그 변수의 게이지·자료 → 게이지의 빈 곳을 누르면 무엇이 부족한지·뭘 공부할지·추천 학습.**
DESIGN "보는 방식 고르기"의 망 보기와 맞음. 1~8절의 갈래 θ가 꼭짓점 값이 된다.

### 꼭짓점 안(사용자 그림의 다섯 + 아래 가려진 하나 = 문장 활용으로 어림)

이해(알아보기)와 활용(만들어 내기)을 갈래마다 나눈 것 — 둘의 차이가 그대로 추천 근거가 된다(이해 ≫ 활용 → 꺼내 쓰기·쓰기 문제).

| 꼭짓점 | 무엇을 재나 | 지금 있는 재료 | 잴 수 있나 |
|---|---|---|---|
| 어휘 이해 | 낱말을 보고 뜻을 앎 | 어휘 고르기·뜻 고르기 첫 답, `vocabLevel` 경계 b, 뜻을 눌러 본 낱말(모름 신호, `gaps.ts`) | 됨 |
| 어휘 활용 | 뜻을 보고 낱말을 씀 | 어휘 빈칸 쓰기(strict type), 단어 시험 쓰기, 튜터가 고친 줄의 새 낱말 | 됨 |
| 문장 이해 | 문장구조·문법을 알아봄 | 문법·문장구조 고르기·순서·틀린 곳 찾기, 문장분석을 연 문장(모름 신호) | 됨 |
| 문장 활용 | 배운 틀로 문장을 만듦 | 꺼내 쓰기(`recall`), 수업 대화 세 번, 틀린 곳 고치기 쓰기, 채팅·통화에서 그 틀을 맞게 씀 | 됨 |
| 듣기 | 들은 말을 알아들음 | 통화 🙉 못 알아들었어요·💬 자막 켠 차례 비율, 영상 자막 뜻 본 비율 — **듣기 문제는 2026-10-30에 뺌** | 일부(행동 신호만) |
| 실전 대화 | 실제 대화에서 이어 감 | 통화·채팅의 고친 비율(✎/내 말), 🔁 다시 말해 맞힘, 💡 힌트·내 말로 말한 비율, 통화 길이 | 됨(폰 통화 기록) |

- 💬 표현(Logbank 기준 탭)은 짧은 것은 어휘, 덩어리 표현은 문장 쪽으로 나눠 넣는다(`partOfKey`와 같은 셈) — 따로 꼭짓점을 만들면 일곱.
- 약한 꼭짓점은 그림처럼 주황 점(다른 꼭짓점 평균보다 한참 낮거나, 수렴 전 범위가 아래로 걸칠 때).
- 수렴 전 꼭짓점은 점 대신 범위(흐린 선분) — 체크만 하고 아직 답이 없을 때 육각형이 확신처럼 보이지 않게.

### 듣기 = 상대 말을 알아들었나(사용자 2026-11-02 "실전 대화와 합치거나, 딴소리·얼버무림을 잴 수 있으면 분리")

- **잴 수 있음 — AI 통화만.** 통화 감독(`roleplay/director.ts`)이 차례마다 이미 JSON을 내고 `assessment`(on_track · stuck · off_script · topic_change)가 있다. 같은 호출에 칸 하나를 더한다(원가 거의 0 — 출력 몇 토큰):
  `"heard": "yes" | "off" | "vague" | ""` — 튜터가 바로 앞에서 **물었거나 답을 기다리는 말을 했을 때만**: yes = 그 말에 맞게 답함 · off = 엉뚱한 답(못 알아들은 것으로 보임) · vague = 아무 질문에나 맞는 얼버무림("yes yes", "I think so", "ok") · 빈 값 = 물은 게 없음·판단 못 함.
- 모델 없는 신호도 같이: 🙉 못 알아들었어요(다시 쉽게 들은 뒤 맞게 답하면 반쯤), 💬 자막을 켠 차례(자막 보고 답함 = 듣기 근거에서 뺌).
- 듣기 점수 = 자막 없이 들은 질문 차례 중 yes 몫(🙉 → 다시 듣고 yes는 0.5, off·vague는 0).
- **헷갈리기 쉬운 것:** ① 학습자가 일부러 화제를 바꿈(topic_change) — 질문을 받고도 바꿨으면 off, 질문이 없었으면 안 셈 ② 받아쓰기 실수로 엉뚱해 보임 — 학습 언어 문장이 아니거나 낱말이 깨졌으면 빈 값 ③ 채팅은 글을 읽으니 듣기가 아님(읽기 — 문장 이해 쪽), 사람끼리 통화(Room)는 모델이 없어 안 잼.
- **분리 기준(제안):** 감독의 heard 판단이 Sonnet 다시 보기와 85% 넘게 맞고(가상 사용자 통화 — qa 196명 묶음 재사용), 한 사람이 질문 차례 20개 넘게 쌓이면 듣기 꼭짓점을 따로 그린다. 그 전·그 아래 사용자는 실전 대화 게이지 안의 한 줄(듣기)로만.
- 순서: heard 칸은 어느 쪽이든 실전 대화 재료라 먼저 넣고(서버 바로, `callDays.v1`에 차례 수·yes·off·vague·🙉 숫자만 — 문장 없음), 보이는 자리는 판단이 맞는지 본 뒤.

### 2층: 꼭짓점 → 게이지

- 그 변수의 채움 막대 하나를 **1~5단계 칸으로 나눠** 채움(어림 범위는 띠) + 주별 추이(작은 선) + 근거(무엇을 몇 번 — 시험·퀴즈·수업·통화).
- 채워진 칸 = 익힘·어림으로 앎, 빈 칸 = 아직. 숫자를 보일지는 결정 대기 1.

### 3층: 빈 곳 → 부족한 것 · 공부할 것 · 추천

- 누른 빈 칸(단계) 기준으로 셋:
