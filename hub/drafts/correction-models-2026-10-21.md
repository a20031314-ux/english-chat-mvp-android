# 교정 모델·도구 비교 — 2026-10-21 (GPT 제외 후보)

- 요청: 사용자 "확인하고, 다른 모델 검토해서 알려줘. gpt 제외 다른 툴들까지".
- **먼저 알아야 할 것:** 지금 채팅 교정은 `gpt-4o-mini`(`OPENAI_MODEL` 기본값). OpenAI가 2026-10-14에 **gpt-4o-mini·gpt-4.1·gpt-4.1-mini 종료를 2027-01-14로 발표** — 지도·미션·표현 묻기·가상 사용자 평가(gpt-4.1-mini)도 같이 걸림. 바꾸는 건 선택이 아니라 일정.

## 어떻게 비교했나

- 시험 문장 121줄(영어 62 · 한국어 59, `tiers.json`의 맞는 문장·실수 하나·많이 틀림·소극적 대화). 각 줄에 같은 교정 규칙(`chat/route.ts` 교정 정책 + `languageFocus.ts` 한국어 힌트)을 주고 후보마다 고친 문장·설명을 받음.
- 후보: 지금 운영(gpt-4o-mini + 오늘 넣은 가드, 실제 운영 답 중 가장 흔한 것), Claude Haiku 5.5 · Sonnet 5.5 · Opus 5.5(이 작업 공간의 에이전트로 — API 키 없이), LanguageTool 공개 API(영어만, 한국어 미지원).
- 평가: 후보 이름을 가리고 줄마다 순서를 섞어, 후보가 아닌 모델(Claude Fable)이 원어민 교사 기준으로 채점.
- Gemini·DeepSeek 등은 API 키가 없어 못 돌림 — 가격만 조사.

- 운영이 틀린 것: 한국어 "음식이 좋아해요" 그대로, 선생님 주어 "줬어요"(→주셨어요) 그대로, 선생님께 긴 문장 뒤쪽 "나 바쁘다 오늘" 그대로, "어제요"·"조금"이 문장 끝에 남음, 영어 "I am not understand…" 시제 섞음, enjoy 설명 틀림.
- Haiku가 틀린 것: "고양이 두 개" 그대로, 선생님 주어 높임 놓침. Sonnet도 선생님 주어 높임 하나만 놓침.
- LanguageTool은 철자·대문자만 잡고 학습자 실수(시제·전치사·관사·어순)는 대부분 놓침, Busan→Susan처럼 뜻을 바꿈 — 교정 엔진으로는 안 맞음.
- 설명 언어: Claude 후보들이 설명을 앱 언어가 아닌 언어로 쓴 줄이 많았음(Haiku 60·Sonnet 28·Opus 29줄) — 시험 지시가 모호했던 탓이 크고, 운영 서버는 설명이 학습 언어로 나오면 다시 옮기는 단계(`restateExplanation`)가 있어 점수에서 뺌. 실제로 바꿀 때 꼭 다시 확인.

**주의:** Claude 후보는 실제 API가 아니라 에이전트로 돌림 — 121줄을 한 번에 보고, 대화 답을 같이 쓰지 않았고, 온도 0.9도 아님. 운영보다 유리한 조건이라 차이가 실제보다 크게 보일 수 있다. 방향(Haiku ≥ 지금, Sonnet·Opus는 거의 완벽)은 믿을 만하지만 결정 전에 실제 API로 같은 점검이 필요.

## 제안 (사용자 결정)

1. **채팅 교정 모델을 Claude Haiku 5.5로 옮기는 것을 실제 API로 시험** — 지금보다 싸고(한 턴 0.67 → 0.49원) 이번 시험에선 더 정확. 필요한 것: Vercel에 `ANTHROPIC_API_KEY`, 서버에 모델 선택 스위치(채팅부터, 미리보기 배포에서 `sim:users --suite tiers`로 14개 언어 비교 → 운영 전환).
2. 한국어 학습처럼 어려운 줄만 **고친 문장 한 번 더 확인**(Sonnet, 고침이 생긴 턴에만)은 비용이 커서(한 턴 +약 10원) 유료 손해 구조(`hub/costs.md`)와 같이 봐야 함 — 1번 결과를 보고 결정.
3. 종료 일정 때문에 gpt-4.1·gpt-4.1-mini를 쓰는 다른 기능(지도 만들기·미션 확인·표현 묻기·롤플레이 평가)도 같은 방식으로 옮길 후보를 정해야 함.
4. 한국어 맞춤법 API(바른·부산대)는 지금 규칙(`koreanSlips.ts`)과 겹치고 높임·뜻은 못 봐서 당장은 넣지 않음.

## 운영 비교: 지금 모델 vs Claude Haiku 5.5 (2026-10-22)

- 방법: 같은 영어↔한국어 점검(`sim:users --suite tiers --only en:ko,ko:en`, 196명·약 636줄)을 같은 씨앗 2개로, Haiku는 점검 사용자만 `--model-routes '{"basic":"anthropic: claude-haiku-5-5"}'`. 채점은 Claude 에이전트가 모델을 모른 채 같은 RUBRIC으로(지금 모델 결과도 다시 가려서 채점).
- 주의: 2026-10-21 저녁 첫 "Haiku" 실행은 시험 스위치가 `rc:` 접두사 때문에 꺼져 있어 실제론 gpt-4o-mini였음(버림, `enko-baseline-mislabeled-2026102118`). 그다음 Claude 5.5가 temperature를 400으로 거절 — 둘 다 고친 뒤 다시 돌림.

| 실행 | 큰 문제 | 작은 문제 | 섞어 쓴 낱말 안 고침 | 응답 중간값 / 90% |
|---|---|---|---|---|
| 지금(gpt-4o-mini + 규칙) 씨앗 18 | 10.2% (65/635) | 24% | 3 | 2.0초 / 3.0초 |
| 지금 씨앗 19 | 6.4% (41/639) | 31% | 0 | 1.9초 / 2.8초 |
| Haiku 씨앗 18 | **1.6%** (10/636) | 20% | **72/72** | 4.7초 / 8.2초 |
| Haiku 씨앗 19 | **1.7%** (11/637) | 22% | **68/75** | 4.2초 / 9.7초 |

- Haiku가 나은 곳: 한국어 높임·불규칙·문장 고침(heavy 큰 문제 27 → 1), 편한 말 줄 주어 바뀜("뭐가 늘었고" → What have you…) 대부분 사라짐, 맞는 말 과잉 교정("별로요", 짧은 답 13 → 1), 엉뚱한 입력·지시문 공격은 모두 잘 피함.
- Haiku가 못한 곳:
  1. **섞어 쓴 낱말을 거의 안 고침** — "이따가 coffee 한잔할래요?", "my 친구" 같은 줄에서 고친 문장은 그대로, natural 칸에만 바꿈. 채점은 작은 문제로 봤지만 학습자에겐 "그렇게 써도 된다"로 보임 → 전환 전에 고쳐야 함(지시문 한 줄 또는 natural과 다르면 corrected로 올리기).
  2. **느림** — 중간값 2초 → 4.5초, 느린 줄 9초. 고친 줄에 따라붙는 다시 답하기 호출까지 Haiku라 두 번 기다림. 원인 확인 필요(스트리밍·호출 하나로 줄이기).
  3. 드물게 편한 말 줄("What does that word mean?")을 고칠 문장으로 다룸(3건), 설명이 틀린 규칙(very much 위치, i before e) 몇 건.
- 결론: 품질(큰 문제 6~10% → 2% 아래)은 전환할 가치가 큼. 다만 ①섞어 쓴 낱말 ②속도를 먼저 고친 뒤 Vercel `MODEL_ROUTES` basic 전환을 권함. 고친 뒤 같은 두 씨앗으로 다시 확인.
- 파일(스크래치·`tmp/`, 채팅 끝나면 사라짐): `tmp/sim-users/enko-haiku-2026102118-b`, `-2026102119-b`, `enko-final-blind18/19`(judge/*.verdicts.json).

### 고친 뒤 다시 비교 (2026-10-22 오전) — 답 먼저(스트림) + 섞어 쓴 낱말 규칙 + 도구 입력 JSON

| 실행(같은 두 씨앗, 모델 가리고 채점) | 큰 문제 | 작은 문제 | 섞어 쓴 낱말 안 고침 | 답이 뜨는 시간(중간/90%) | 교정까지 |
|---|---|---|---|---|---|
| 지금 모델 | 10.2% · 6.4% | 24% · 31% | 3 · 0 | 2.0 / 3.0초 | (답과 같이) |
| Haiku 첫 비교 | 1.6% · 1.7% | 20% · 22% | 72/72 · 68/75 | 4.7 / 8.2초 | (같이) |
| **Haiku + 스트림 + 고침** | **4.2% · 4.9%** | **17% · 14%** | **0/72 · 1/75** | **1.7 / 2.4초** | 2.1 / 2.8초 |

- 고친 것: 섞어 쓴 낱말은 거의 다 고침(규칙으로 찾아 `noticed`로 알림 + 지시 바꿈), 답은 지금 모델보다 빨리 뜸. Claude가 한국어 답에서 JSON을 깨던 것(따옴표)·`{respond:{…}}`로 싸서 주던 것 고침.
- 첫 비교보다 큰 문제가 늘어난 것(1.7 → 4.5%)은 채점자 차이(같은 지금 모델 두 번이 10.2 vs 6.4%)와 새로 보인 문제가 섞임. 이번에 큰 문제로 잡힌 것:
  1. **편한 말 줄 표현 카드의 주어 바뀜**("요즘 뭐가 늘었고…" → What have *you*…) — 같은 줄이 어떤 때는 맞음. 표현 카드(howToSay)도 Haiku.
  2. **맞는 "커피가 마시고 싶어요"를 를로 고치고 틀린 규칙 설명**(4건) — 지금 모델에도 있던 것.
  3. **영어 단골 실수를 natural에만 고침**("I'm so boring", "explain me", "many food → many foods") + 시제 섞임 남음.
  4. 짧게만 답하는 사람과의 대화에서 튜터가 역할을 헷갈림(작은 문제 다수).
- 판단: 큰 문제는 지금 모델의 절반 아래, 답은 더 빠름 → **전환해도 지금보다 나음.** 위 1~3은 전환 뒤 고칠 목록(규칙·지시). 옛 앱(2.70 이하)은 스트림이 없어 Haiku면 다시 답하기까지 기다림(약 4.5초) — 전환 시 옛 길도 다시 답하기를 빼면 약 2초.
